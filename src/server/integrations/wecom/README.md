# 企业微信协议、媒体与回执（BOW-909 第一片）

本目录提供可调用的协议适配器，尚未接入生产材料整理链。导入模块不会加载环境文件、建立连接、注册 worker、写数据库或调用模型。BOW-895 的鉴权/心跳记录只证明外部连通前提，不代表已经收过真实私聊文字、图片或完成回执。

## 协议依据

参考企业微信官方 Node SDK 固定提交 `80615b987ef69c6028ad764924609247c0725955`，不依赖该 SDK 的运行时代码：

- [消息与事件](https://github.com/WecomTeam/aibot-node-sdk/blob/80615b987ef69c6028ad764924609247c0725955/src/types/message.ts)
- [请求与回执](https://github.com/WecomTeam/aibot-node-sdk/blob/80615b987ef69c6028ad764924609247c0725955/src/types/api.ts)
- [媒体解密](https://github.com/WecomTeam/aibot-node-sdk/blob/80615b987ef69c6028ad764924609247c0725955/src/crypto.ts)
- [长连接与心跳](https://github.com/WecomTeam/aibot-node-sdk/blob/80615b987ef69c6028ad764924609247c0725955/src/ws.ts)

`aibot_subscribe` 成功 ACK 后才进入 ready；每个请求只接受相同 `req_id` 的 ACK。文本、图片、文件和混合消息被转换成有序、冻结的数据，引用消息及消息附带的角色、回调地址不作为授权依据。不支持的消息类型明确报错。`disconnected_event`、鉴权失败、连接故障或超时会关闭连接；不会自动重连抢占同一机器人。

## 调用边界

`createWecomClient` 必须由服务端组合层提供可信的机器人 scope、botId、secret，以及当前授权回查 `authorize(source, action)` 和 `onMessage(message, signal)`。缺少授权回查就不能创建客户端。`source` 只包含渠道定位信息，不能直接当成业务身份或权限。

授权在接收后、进入下游回调前执行，并在每条排队回执实际发送前重新执行。私聊回执的授权动作还带批次编号及预期版本；组合层必须使用 903 的真实身份绑定/撤销回查，并核对当前批次的发送者归属、权限和版本。本目录不定义第二套角色权限，也不默认放行。连接关闭会中止生命周期 signal；业务回调必须自行遵守 signal 和事务规则，关闭连接不等于数据库回滚。

`wecomMessageKey(scope, botId, msgid)` 是稳定的操作键，不随回调 `req_id` 改变。scope 必须来自可信服务端配置，并能区分机器人所属租户/应用。该键需要接入正式事务的唯一约束、消息记录和回执记录，才能实现跨重连、跨进程幂等。客户端的 WeakSet 只防止伪造消息对象，不去重；重复投递仍交给下游判断，不能把内存状态当成生产幂等。

发送操作等待实际 ACK。非零 ACK 返回失败；超时的发送结果可能未知，适配器关闭连接且不盲目重试。后续重试必须依据正式消息/批次/回执事务事实。

## 群聊与私聊

- `acknowledgeGroup` 只生成官方 stream 格式的固定「收到了」，没有任意群聊文本发送入口。
- `sendPrivateReceipt` 只向原始消息的 `from.userid` 发固定批次状态和深链，调用者不能指定另一个收件人；收到的普通 JSON 副本不能作为客户端的原始消息凭证。
- 深链复用 903 的 `buildEntryDeepLink`，只带 `material_batch` 定位、批次编号和预期版本。消息原文、分数、媒体密钥、访问令牌不进入链接。
- Web origin 必须是服务端确认过的 HTTPS origin；没有配置时私聊回执失败。测试中的 `.invalid` 地址只是合成值，不是已部署工程入口，也未证明页面已打开。

## 媒体下载与解密

`createWecomMediaDownloader` 在工厂创建时捕获经确认的精确 HTTPS origins，最多八个；单条消息不能覆盖允许来源或传输策略。本目录没有猜测 CDN 域名或宽泛的供应商通配名单。生产组合前必须根据官方协议及实际受控验证确定来源，未配置就拒绝创建。

每次下载检查全部 DNS 结果，拒绝内网、回环及保留地址，再固定所选 IP、地址族、TLS servername 和证书校验，并核对实际对端 IP。默认传输不继承代理、不跟随重定向。媒体 URL 及 aeskey 都是短时取件资料，不返回为永久原件，不进入模型、日志或公开链接；下游须通过 873 的正式私有归档流程得到真实原件编号。

加密字节按实际流量限额读取，而不是只相信 Content-Length；声明长度存在时也要一致。AES-256-CBC 使用 32 字节 Base64 key、key 前 16 字节作为 IV，并逐字节校验官方 32 字节块的 PKCS#7 填充，不能用 Node 默认 16 字节填充代替。解密器独立验证密钥、密文及明文限额。输出只有明文字节、长度和 SHA-256，不带下载凭据。

| 预算                         | 当前范围                         |
| ---------------------------- | -------------------------------- |
| WS 帧                        | 128 KiB，含包络                  |
| 混合消息                     | 最多 20 项                       |
| 待处理消息 / 待发送请求      | 各最多 32 条                     |
| 建连 / ACK / 心跳 / 关闭等待 | 默认 8 秒 / 5 秒 / 30 秒 / 1 秒  |
| 单份媒体明文                 | 默认及最大 32 MiB，可降低        |
| 密文实际读取                 | 明文限额 + 最多 32 字节填充      |
| 单次下载                     | 默认 10 秒，最大 30 秒，支持取消 |

取消会中止 Node HTTPS 请求。系统 DNS 查询已开始时不能强制终止 libc 查询，晚到结果会被忽略。这里没有进程/RSS 硬隔离，也没有宣称业务处理硬时限。

## 验证与证据边界

定向命令（单测最多两个 worker）：

```sh
pnpm exec vitest run src/server/integrations/wecom --maxWorkers=2
pnpm exec vitest run src/server/integrations/wecom --maxWorkers=2 --coverage --coverage.include='src/server/integrations/wecom/{protocol,client,media,receipts}.ts'
```

96 项测试包含真实本地 WS/HTTP 合成服务端、独立 OpenSSL 密文向量、实际流量限制、重定向拒绝、取消/超时、鉴权 ACK、排队后撤权、关闭和强制 terminate。默认 DNS/HTTPS 传输参数及对端检查用受控 I/O 验证，不声称已访问真实公网 HTTPS 或企业微信。合成字节不含真实员工材料。

另以无 Vitest mock 的独立脚本组合真实 903 身份服务、本地 WS/HTTP 和合成绑定 I/O，核对未知发送者零下游调用、真实字节解密、群固定回执、原发送者私聊、规范深链及绑定版本变化后的拒绝。负控临时移除发送前授权后，排队撤权测试按预期失败，再原字节恢复源文件；该负控不计作审查轮次。精确受检 SHA、覆盖率及命令结果记录在 PR。

## 仍需整合的实际入口

以下事项未由本片完成，不安装空成功端口：

- 可信的 evaluationNodeId、人员归属、批次版本和完整共有人权限，不能从消息中的姓名或未知节点猜测。
- 873 私有材料暂存/归档、真实 uploadId/sourceId，以及下载内容的校验与原件版本绑定。
- 正式消息/回执账本与批次事务、唯一 producer，接入 842/845 及 905/866/901 的实际整理管线。
- 必要公共出口、单一 worker/运行注册和服务端组合，由 X1 按明确窗口整合；本片没有修改共享文件。
- 经确认的官方媒体 origins、833 工程部署 origin，以及 Web 批次入口和当前权限读取。
- 真实端到端：已授权发送者向指定测试机器人发送文字/图片，持有 `resource-wecom-test` 锁后建立唯一连接，核对私聊回执和真实页面。此前 WeCom UI 权限请求已取消，不能通过其他 UI 工具绕过；本片不加载任何凭证、不连接真实机器人。

合入仍受 895/903/873/842/845/905/866/901 依赖及独立审查门禁约束。BOW-909 不因局部协议测试通过而关闭。
