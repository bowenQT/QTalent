# 入营选拔标准生命周期（BOW-918）

输入契约：BOW-917 冻结 `832209d177944b5ce18577794acb88314a6460da`，通过显式合并引入。该冻结已修正判断对照分布投影，仍待当前 head 最终独立验证与合入；selection-standard.ts 与 standard-attribution.ts 相对 da3012e 字节未变。本模块没有改契约或实现判断对照、AI 起草。

## 当前边界

`selection-standard.ts` 提供无数据库副作用的领域计划；`server/usecases/selection-standard.ts` 编排已验证输入、当前服务端权限、领域计划、审计与操作回执。它依赖 `SelectionStandardPorts`，目前没有正式 PostgreSQL 适配或客户端 action/query。注入的内存事务模型只用于单测，不能证明两人并发、数据库回滚、持久化或重启验收。

公共出口由 X1 追加；schema、922 读取与时间表示、持久化适配必须先取得互斥窗口。最终迁移由 X1 在主链 904/902 之后生成。917/922 合入并完成接线回归之前，本卡不能标完成或 ready-to-merge。

## 身份、范围与返回数据

- 入口从可信 session 解析 accountId。用例在事务取得类别和操作键锁后取业务时钟，调用服务端 `loadAuthority`，校验加载的账号与当前账号一致。
- 领域层检查当前 grant 的账号、角色、范围和有效期；系统管理员不借用业务角色。HR 编辑、提交、撤回，管理者确认、带理由退回或撤销。
- `creationFacts` 必须解析归因 → batch → cohort 并核当前权限，不以归因的旧署名代替当前授权。返回的归因须仍为人工确认且含 evaluation_standard，修订号匹配。
- HR 预览中的结果分组、绑定和下一期稳定标识都必须属于服务端可验证的当前范围。HR 动作及幂等重放重新检查响应涉及的每一个 cohort；某个范围撤销后，不能因另一期 grant 还在而返回原预览。没有明确下一期授权事实时关闭该路径，不从 UI role 或名字推断权限。
- 管理者返回视图由显式字段构造，只含保存的同一份影响预览、人工稿和批次聚合摘要，去掉 HR 私有归因、AI 原稿与案例引用。全量绑定快照只供管理者撤销事务使用，不能混入 HR 全局预览。

## 生命周期与内容

创建是 `draft + humanVersion:null`，不冒充 HR 已编辑。HR 保存后才产生署名人工稿、应用经过原版本核验的变更，并同时保存新的 `contentRevision` 与影响预览。提交和发布校验 `expectedRevision`、`expectedPreviewId`；确认人看到的是保存的快照，不在确认时静默刷新统计。

发布前重核当前选拔版本、保存的人工内容和相同预览范围内的当前影响事实；变化时返回 conflict。只生成 xe_selection 的类别切换，旧版 active → superseded、新版 pending_confirmation → active；不会写维度、锚点、分数、档案或历史结果。

撤销限定 `[publishedAt, publishedAt + 5000ms)`，同时核对当前发布 ID、修订号及当前类别版本。计划配对恢复上一版、新版回待确认、类别当前读取/新建期次默认恢复，并保留当前所有期次绑定。已发布内容即使撤销也不能原位修改；撤回后若要再编辑，应另起新版本，避免已经绑定 v2 的期次内容漂移。

## 持久化适配必须落实的事务合同

`transact` 在调用业务回调前取得 xe_selection 类别栅栏和 actor/operation 锁；发布、撤销、新建期次采用必须共享这个类别栅栏。使用 Read Committed、锁后重载权限与时间、修订及当前发布身份 CAS。领域计划、不可变内容、类别生效读取/默认、配对生命周期、审计、操作结果必须同事务提交；任一步失败整体回滚。

操作键按账号隔离；保存 action 与规范化输入的指纹、来源期次和返回内容涉及的可见期次集合。重放先核当前权限，同键异语义返回 conflict，不重复写审计或状态。

当前版本只消费 BOW-922 的 `readEffectiveRuleVersion(tx, {category:'xe_selection', at}, clock)`；不复制查询、不按版本名猜分类、不退回单一 published。写操作可如实返回该读取的 conflict。只读标准响应是否扩展 conflict 仍需契约接线协调，不能把重叠伪装成 not_found。

本模块的 `categorySwitch.activate` 是期望的恢复效果，**不是覆盖922单区间行的指令**。922当前每版只有一段生效区间，如何保存 v1 → v2 → 撤销恢复 v1 的可解释历史须由 X1 统一时间模型；不能只恢复默认指针，也不能伸展旧区间造成重叠或覆盖旧历史。

期次按稳定 cohortId 唯一绑定。重复采用返回原记录，发布/撤销不更新既有绑定；第六期保持 v1、第七期若已绑定 v2 也继续 v2。`readSelectionCohortVersion` 先做该期次范围授权，仅读保存的绑定，没有绑定就 not_found；不拿全局当前版补历史。
