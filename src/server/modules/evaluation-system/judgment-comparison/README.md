# BOW-919 判断对照的提前开发边界

本目录实现原量表对照、三角色投影、当前授权后的统计及只读端口编排。显式前置为 917 最后冻结 `832209d177944b5ce18577794acb88314a6460da`；923 当前输入为 `bow-923-v2`，固定 `339a405598ae9ac7432c7f39a27e6c1afcc0f49d`。不复制契约源码，不从 expected JSON 取业务事实。

## 输入与计算

`ComparisonFacts` 从实际冻结 `ComparisonCase` 去掉 outcome，另接独立 `nonComparable` 人工事实（理由、标记者、时间）。输入携带预计算 outcome 会被拒绝；未知量表 / 档位不能变成反向证据，没有人工不可比标记时返回待核对。

最高 / 刚过线档按 HR 已确认对应表对照；中间档只列后段分布，计入可对照样本门槛。缺段优先归为缺段，不计不一致或样本门槛。两段保留各自原件、fragment、本人行、节点及期次版本；原量表不写成维度分。

输入全是只读事实；本模块没有档案、象限、规则发布、归因写入或模型调用能力。`confirmedAttributions` 只接收端口已核实的人类归因，用于管理者授权汇总，不生成归因。

## 权限与统计

每次读取都从服务端端口重载身份、受众、时钟及当前有效的节点范围。客户端参数只有冻结 read input，不能提供角色、时钟或授权列表。节点授权必须同时匹配人、节点与 `[validFrom, validUntil)`；历史参与前段只用于“我的”筛选，不授予当前段读取权。

- HR：仅保留两段当前可读的案例，再统计批次和各评价人。评价人按中文姓名、同名按 ID 稳定排列。
- 评价人：只保留本人参与前段的案例；无权段剔除引用、评语及原件，并将 outcome 隐藏。任一段隐藏就不计算该案例，也不计样本。
- 管理者：仅含当前授权的批次不一致人数与已确认归因类别，不带案例、来源、评价人或评价人数字。

个人 `sample.caseIds` 只包含当前可披露的可对照案例。distribution 从这组案例重算，因此 excluded 四字段为零；批次 counts 独立保留可读案例的缺段 / 不可比。少于 5 例只有“样本不足”和案例 ID，没有分布。不接受已有汇总作输入，以避免跨人或隐藏统计混入；已同步 917 最后 R2 冻结并复验受影响范围。
