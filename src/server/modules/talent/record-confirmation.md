## 撤销

业务时钟与真实墙钟分开。保存时间与五秒截止来自同一真实墙钟，半开区间`0 <= elapsed < 5000ms`。只允许原账号与原人员绑定；撤回本次新事件、本人确认和本次复核，不物理删除原件/片段/AI或人工历史。第二评价人撤销不撤原事件；首份新建事件有他人后续确认、相关复核被HR处理、原确认失效或任务版本改变时整批冲突，失败不留下部分修改。

如存在真实`resourceId=draftId`的本人待确认事项，先按899实际分派检查，在同事务完成，并记录实际返回的事项归属和完成revision。其他评价人可依本人的当前节点评价权独立确认，不受待办承接顺序约束，也不替承接人完成或改变事项。撤销须核本次原完成版本；首份事件与草稿一同撤回时事项取消，第二评价人撤销后事件仍有效时事项通过899公共undoEvaluationWorkCompletion恢复待处理。端口在同事务中重新核对原完成版本、原关系与当前本人节点权限，并以CAS推进事项revision。后续HR/来源变更不被覆盖。没有查到的事项不编造ID、归属或revision。原话按保存的不可变输入原样返回，撤销不自动重新整理。
