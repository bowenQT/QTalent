## 决策与信任边界

输入是将来服务端在同一事务锁后重新读取的事实快照，**不是请求 DTO**。这里不提供路由或把客户端的角色、人员选择、已入职标记、来源 locator 当作可信事实。实际账号、时钟、HR 逐行确认、招聘记录、目录任职、已有导入与待核对记录仍须由真实服务端适配器读取。权限发生变化时须重新调用，不能缓存 `planned`。

- 只有当前范围内 HR 可以得到导入计划；员工、评价人、管理者或系统管理员均不能借此取面试分。面试节点、主体和当前 HR 范围复用 899。不能借其他节点或到期关系放行。
- 三项匹配为观察到的姓名、职位编号、面试时间与候选记录一致，且有该候选的 HR 逐行确认。缺观察字段、未确认、重复候选标识或目录姓名不一致，明确 `not_ready`。不从面试结果推断录用。
- `rejected` / `offer_pending` / `offer_declined` 均跳过，包括目录里有同名员工的淘汰申请。`hired` 申请仍必须有该人已经开始的目录任职记录；未来任职不是已入职。没有新增“曾离职即从未入职”的产品规则；当前读取/导入权限另由 899 判断。
- 未识别的选项与缺少元数据保持未就绪；明确不适用的管理维度原样保留。输出完整原生解析值、原评级、建议职级、面试结果及各自 bbox，既不换算维度分，也不生成象限、匹配、值得关注或模型输入。
- 原面试官与当前导入账号/人员分别记录。原导入动作不会变成面试官在本系统确认；即使二者是同一个人也分别署名。
- 未知或重名面试官生成可通过 897 schema 的待核对提案，零历史评价计划。只接受当前待核对项对应的 `link_existing_interviewer`；目标必须已在目录中，不新建人。项、批次、行、节点、材料、原件版本、片段/范围、原观察名和 revision 全部一致后，才恢复原批次。无命令或延期保持待核对。
- 重复身份是 `candidateId + 面试时间原文 + interviewerId + template`，使用 JSON 元组后摘要，避免分隔符碰撞；不按评分去重。当前固定解析器时间文本按原样比较，不猜测正式模板的时区/日期转换。事务中的唯一性与并发 CAS 尚未实现，不能把纯函数当作并发保证。已存在的同身份评价返回 `duplicate`，恢复也不生成第二份计划。

## 真实未就绪项

900 当前没有候选人姓名、职位编号字段；目录/招聘记录也缺相应生产读取。没有这些事实的真实调用只能返回 `candidate_identity_missing` 等未就绪状态。测试里额外的 `DEMO-JOB-01` 和匹配记录明确是自建合成输入，不证明生产字段或官方模板存在。

900 的 `page + bbox` 与 897 的 `pdf + textRange` 不等价。本函数不执行转换，只校验额外提供的 canonical 来源属于同一原件、同页、历史面评分类；其来源真实性、逐字段文字 offset 与原件授权必须由后续适配器保证。测试正例使用 897 本身的独立合成来源，**不是把 896 PDF bbox 转成 offset，也不是证明这些 PDF 已持久化**。没有 canonical 来源或传来 bbox 的情况返回 `pdf_source_unverified`。材料 ID 必须单独给出，不以原件版本 ID 代替。
