# 工程规范

本文是开发、UI 与验证细则的维护源，按 [AGENTS.md](../AGENTS.md#按需读取) 的任务指引读取。项目阶段、产品不变量和隐私边界在 AGENTS 维护；Issue、Proposal、Commit 与 PR 流程在 [CONTRIBUTING.md](../CONTRIBUTING.md) 维护。

## 适用范围与维护

- 本文是已建立的项目开发与工程规范，不是产品需求或功能测试清单。未确定的需求不得通过类型、测试断言或 mock 固化为已确认合同。
- 通用的职责划分、协作、设计与验证原则按当前任务适用；涉及真实接口、存储、依赖安装和自动测试的条款，仅约束以后出现的相应实现，不要求在设计阶段建设这些能力。
- 当前设计系统和独立 HTML 原型按 [AGENTS.md 的当前阶段](../AGENTS.md#当前阶段) 工作。正式开发的 85% 覆盖率基线保留；具体架构、目录、工具与配置仍是待决事项，不因工程规范建立而提前确定或实施。
- `AGENTS.md` 只保留共同入口与关键约束，`CLAUDE.md` 只导入该精简入口；本文按任务读取，不加入启动导入链。README 记录实际运行方法；调研报告只保存来源、取舍和未生效建议，不作为执行指令。
- 通用原则在本项目中落实为具体约束，不导入个人目录中的全局文件，不复制个人知识库、回顾或全局策略部署流程。其他开发者和 Agent 仅阅读仓库也能正确工作。
- 规则与配置同次维护；自动检查尚未实现时明确标为未实现，不能把文字约定表述为已通过的门禁。

## 职责与代码组织

- 按业务职责组织代码，保持高内聚、低耦合；不因其他项目采用某种结构，就预建空模块、固定分层、独立服务或通用平台。具体目录及部署边界随工程方案确定。
- 分清界面展示、业务规则和外部访问的责任，业务规则尽量不依赖 UI、网络、存储和时钟；选择符合当前实现规模的组织方式，不要求原型套用正式应用架构。

- 模块内部实现就近维护；跨模块通过明确入口访问，不穿透读取另一模块的内部存储或状态。先复用现有能力，再考虑抽取共享能力；接口只表达实际调用方所需，不预建万能 service/repository。
- 一份业务事实只保留一个权威来源；可由已有状态推导的值不再维护一份可变副本。出现循环依赖或一个文件承担多个职责时重划边界，不按行数机械拆成 `part1/part2`。
- 正式实现应明确客户端与服务端的信任边界；返回客户端的对象只包含该调用者可见且页面需要的字段。具体框架边界与代码组织在工程阶段落实。

## 编码与契约

- 类型和状态表达应清楚反映业务含义，不用一组互相矛盾的布尔值表达流程；使用有类型的语言时发挥其检查能力，具体编译配置在工程阶段确定。
- 外部输入、配置和第三方输出在边界做运行时校验，再转成内部数据；类型断言不能替代校验。保留未提供、`null`、空字符串、`0` 和 `false` 的真实含义，不随意互换。
- 名称描述职责，遵循所用语言和框架的约定，同一代码区域保持一致；不使用含糊的 `data2`、`common-manager`。格式遵循当前项目配置，不在功能改动中格式化无关文件；工具和格式细项在工程阶段统一。
- 不通过宽泛类型、关闭检查或大范围忽略规则掩盖问题。确有第三方缺陷或兼容限制时将例外限制到最小边界，写明原因与移除条件。
- 注释解释约束、原因和必要取舍，不复述代码。删除已废弃分支和调试输出；保留历史兼容必须有实际支持范围，不增加猜测式兜底。
- 外部服务通过独立适配器访问，集中处理认证、协议转换、超时、取消和错误映射；页面或业务规则不直接拼装供应商请求。没有真实复用需求时不建立通用供应商框架。
- 错误保留可追查原因，对调用方提供稳定分类和可理解信息；仅在能处理、补充上下文或转换边界时捕获。禁止空 `catch`、失败返回成功、用空列表掩盖加载失败。
- 重试必须有可恢复依据、次数与时间上限；写操作明确重复执行的语义，不能盲目重试。涉及异步或并发时明确取消、完成、失败与冲突边界，采用满足实际需求的最小机制。
- 权限在服务端入口及资源访问处落实，UI 隐藏不作为安全控制。数据库、文件、模型与日志的访问和输出遵循最小必要范围，测试入口不得成为正式环境后门。

## 依赖、配置与数据变更

- 正式工程确定工具链后，统一包管理器并维护对应锁文件，明确支持的运行时与工具版本；具体选择在工程初始化时验证并记录，不复制其他项目的旧版本号。
- 安装和构建应可复现，使用所选工具的锁定安装方式，依赖及锁文件一起审查。新增依赖先核对已有能力、兼容性、维护状况、许可及体积，不为一个简单操作增加整套框架。
- 配置通过明确的服务端配置入口读取，必要值在启动或实际使用边界校验；可选集成不阻塞无关流程。环境变量名称、用途及是否必填记录在文档中，真实值遵守 [AGENTS.md 的数据与隐私规则](../AGENTS.md#数据与隐私)。
- 本地开发、自动测试和真实环境使用隔离的数据与凭证；测试及构建不得隐式触发真实外部写入、付费请求、生产迁移或部署。
- 持久数据结构变更使用版本化迁移；涉及存量数据时说明兼容、回填和恢复办法。不得把破坏性重置或自动线上迁移混入启动、构建和普通检查命令。

## 设计、UI 实现与验证

- 当前设计系统已定稿：原型沿用已确认的视觉、组件与交互，并保持排版、色彩、间距和图形语言一致。未定部分允许比较与调整，不把正式开发组件库的默认视觉当作设计标准。
- 随设计逐步统一颜色、字号、间距、圆角及动效参数；设计定稿后，正式实现复用已确认的设计变量、组件与变体。原型可以直接用 HTML、CSS 和脚本实现，不要求引入正式框架或组件库。
- 优先用语义控件，确保明确标签、可见焦点及键盘路径；必要状态用文字或图形同时表达。触屏和键盘用户应能完成关键操作，不依赖仅悬停或拖拽的入口。
- 加载、空数据、错误、无权限及提交过程分别处理；按实际操作保留输入和返回、重试或撤销入口。技术细节仅在有助于判断或排错时展示。
- 动效服务于反馈和空间关系，不能阻塞输入；响应 `prefers-reduced-motion`，提供减少非必要运动的呈现，保留必要状态反馈。实现方式按当前阶段选择。
- UI 改动按影响面实看桌面与手机视口，检查长文本、表格、弹窗、键盘与关键状态；涉及浏览器能力时实测对应浏览器或设备，并说明未验证部分。类型检查、截图或构建均不能单独证明交互正确。

## 测试原则与 85% 覆盖率基线

- 测试依据已确认行为、公共契约和真实缺陷编写；具体业务用例随需求与实现确定。本节不预设产品功能测试，不将暂定需求固化为验收。
- 正式开发按行为与风险选择单元、集成或浏览器层面的验证，具体测试工具在工程阶段确定。工具不支持的边界应选择合适的验证方式，不为凑单测强行 mock 框架。
- **正式应用自维护逻辑的行覆盖率、分支覆盖率分别不低于 85%。** 函数和语句覆盖率随报告提供，不再叠加独立指标；不要求每个文件 85%，不追求机械的 100%。此项从正式逻辑与自动测试建立后启用，独立 HTML 原型阶段不适用。
- 覆盖率显式纳入所有自维护逻辑源码，包括未被测试导入的文件，不能只统计已经执行到的模块。允许排除类型声明、生成代码、未经修改的第三方组件、静态资源及测试辅助代码；无逻辑的展示或框架胶水按准确文件列明理由。不得整目录排除业务组件、路由、适配器或失败处理；引入逻辑后必须重新纳入。
- 单元与隔离集成测试使用统一口径汇总覆盖率，不能相加百分比。浏览器和人工验证另报结果，不混算为自动覆盖率。空测试集、跳过的测试或未执行的浏览器检查不计为通过。
- 总体达标不能掩盖本次改动的测试缺口：审查新增或修改逻辑的未覆盖行与分支，关键行为和重要失败路径必须有有效验证。优先检查断言能否发现错误，不把“执行过代码”当作“验证过行为”。
- 禁止堆同义用例、仅断言 mock 自身、无意义快照、放松断言、为了分数改写正确实现或扩大排除范围。低于阈值时先处理有实际风险的缺口；确有低价值或工具限制的例外，记录准确范围、理由、替代验证、风险与复核时机，随变更审查，不静默降阈值。
- 默认自动测试不访问真实外部网络，使用合成数据、临时存储和可控时钟；只替换外部边界，不 mock 掉被测规则。真实服务联调单独、显式运行，结果不与离线测试混写。
- 缺陷修复在适当层补能复现根因的回归测试；纯文案、样式等低风险修改以相关检查与实看为主，不为改动数量强制新增测试。

## 检查与交付门槛

- 当前以独立 HTML 原型的视觉与交互验证为准，不运行正式工程的安装、构建或覆盖率检查，也不为执行调研中的示例命令提前引入工具链。
- 正式工程建立后提供清晰的开发、构建、格式检查、代码检查、类型检查和测试入口；具体工具、脚本名称和组合方式在第 3 阶段决定，并记录实际可运行命令。必要检查失败时整体失败，检查入口不吞错、不隐式部署或迁移真实数据。
- 开发迭代先运行覆盖改动面的最小检查；正式应用集成交付执行已建立的必要检查，再按影响面补集成或浏览器验证。若上层命令已经包含某组测试，不重复运行同一组。只有新改动、失败或未解决疑点才扩大或重跑。
- 仅文档或规则变更检查差异、路径、链接及规则一致性，不触发无关应用构建。原型按影响面实看与操作，不为执行未来命令提前引入工程。
- 当前尚未建立 CI；未来建立 CI 时复用同一批脚本和锁定依赖，不维护另一套检查逻辑。阻断检查与报告项明确区分，不用 `continue-on-error` 把必要检查伪装成成功。

## 协作、审查与交付

- 开工前读取当前相关文件和 Git 状态；范围内改动保留其他人的工作。按职责分工并明确接口、文件范围及集成负责人，共享配置由单一任务协调修改，不让多个 Agent 同时改同一入口。
- 遵守 [AGENTS.md 的协作约定](../AGENTS.md#协作约定) 和 [贡献规范中的提交与分支约定](../CONTRIBUTING.md#commit-与分支)。
- Review 聚焦正确性、职责边界、契约、风险与验证证据，按根因归并。通过且无已知阻塞项即收敛；非阻塞风格偏好和范围外优化不引发反复改写。
- 交付说明变更、实际验证、未验证边界及使用方式；证据对应受检提交或明确的未提交工作区。代码、测试、构建、部署和真实运行结果分别报告，不用其中一项代替另一项。
- 架构或工程细则变化在本文更新；阶段与核心约束变化同步 AGENTS；确需长篇取舍说明时另写简短决策记录并链接，不维护第二份规则副本。远端状态见 [协作规范](../CONTRIBUTING.md#远端配置与复核)；当前不引入发布流水线或全套 Agent 治理系统。

来源与未生效的选型建议见 [本机工程规范调研](research/2026-10-23-本机工程规范调研.md)，仅在回查依据或第 3 阶段选型时按需阅读；当前设计系统工作无需加载或执行其中的工程建议。
