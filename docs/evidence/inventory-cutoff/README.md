## 复核步骤

1. 清空演示数据，以 HR 打开 `/y/app/review.html?id=b-xe6-end&as=hrbp`。默认截止 `09-05` 时仍为 30 人资料不足。
2. 点击证据截止后的「改」，保存 `2026-07-10`。应显示 93 人资料不足，陆晚晴（演示）行显示 0 条分。
3. 进入「去象限校准」，线索雷达团队应没有可落位头像，5 人均在「还在等材料」区；确认弹窗的证据截止应为 `07-10`。
4. 确认冻结，刷新页面。该团队仍无落位头像，资料不足的维度统计保持 0；本地快照的 `cutoff` 应为 `2026-07-10`。
5. 重置演示数据，重复上述操作但改用 `2026-08-07`。校准条目数量、维度均值和条数应与 `NT.store.refPos(人员ID, '2026-08-07')` 一致；确认快照应记录 `08-07`。
6. 冻结后增加新的已确认事件再刷新，盘点人员行里的维度条数与冻结快照应保持不变。
7. 日期边界：尚未冻结时，截止当天的已确认事件应计入，次日事件不计入。原有中期盘点的人员条数继续读取中期快照。

上述七类场景已在本地浏览器逐项断言通过，控制台无脚本错误。截图用于核对视口和可见结果，交互结果由上述操作另行验证。
