## 1. 对接范围与验证边界

先接通组织、人员、任职历史和岗位职级字典，再单独接绩效结果与评语。北森提供人事底账；QTalent 的事件证据、人才项目、评价规则和校准结论由 QTalent 维护。

- 北森 → QTalent，只读同步，不回写。组织、人员、任职和职级以北森为准；人才项目名单、导师关系、评价与校准不从北森覆盖。
- 北森绩效与晋升按原口径留作历史档案，只给有权限的管理者和 HR 查看；不换算成维度分，不进入象限、值得关注、判断对照、找人证据或任何模型输入，不用于排序。
- 当前岗位与职级可用于选择适用的专业度标准；这不代表允许用历史绩效或晋升推断能力和潜力。
- 项目已在 U-8 中确认公司开通了北森开放接口；这不等于本轮已验证某个连接器、接口、字段或人员范围可用。
- 本清单不改变需求、权限或阶段门禁，也不把分期方案的其他 Draft 内容升级为 Accepted。比赛仍使用化名种子数据，真实北森同步列入赛后试点。

已识别的产品是北森 iTalentX 一体化 HR SaaS 的 PC 门户；实际页面的招聘入口含 `Recruitment/InterviewV6`，绩效为 `PerformanceCloud`，OKR 为 `TargetManagement`。这些模块标识及 API 路径中的 `v1`、`v2`、`v5` 不能证明公司租户整套产品的精确发布版本或购买套餐。

## 2. 数据与接口清单

P0 表示真实试点的基础条件；P1 表示随后接入的历史人事资料。这是对接顺序，不是新增的实现排期或取数授权。

| 优先级 | QTalent 需要的数据 | 北森文档支持的内容与接口 | 租户内还需核实 |
| --- | --- | --- | --- |
| P0 | 组织目录与归属 | 组织 ID、编码、名称、行政上级、有效期、启停状态、部门负责人、组织 HRBP、简介。[组织查询（S01）](https://open.italent.cn/#/open-document?menu=document-center&id=dc1e628c-21a6-49cc-ae0c-7fc4a037d1bd) | 公司采用行政还是业务组织树；组织简介是否包含正式职责；历史组织版本是否完整 |
| P0 | 人员基础档案 | `userID`、姓名、工号、人员状态、入职／转正日期、任职部门、岗位关联、学历／学校／专业等。[员工与当前任职（S02）](https://open.italent.cn/#/open-document?menu=document-center&id=d2405033-0bb3-4574-ad82-b959799e8882) | 实习生是否纳入；重入职、换工号时如何保持同一人的关联；只申请项目白名单字段 |
| P0 | 汇报与管理关系 | 任职中的直线经理、虚线经理、是否部门负责人；组织上的负责人和 HRBP（S01、S02） | 组织 HRBP 不等于人员 HRBP1／HRBP2；后两者及 BUDDY 可能是公司自定义字段，需确认实体和字段编码 |
| P0 | 入离调转与任职历史 | 多条任职记录、生效／失效时间、部门、职级、异动类型、最后工作日、删除标记。[任职历史查询（S03）](https://open.italent.cn/#/open-document?menu=document-center&id=e0b9ab6d-0ca7-41cc-8104-6637961aee8d)；需要批量同步多条任职时评估[多任职时间窗查询（S04）](https://open.italent.cn/#/open-document?menu=document-center&id=dcc85504-8d36-4393-b4dd-3c510d18fb66) | 默认筛选可能漏离职和历史记录；最新任职可能尚未生效，不能当当前组织；不必把两种历史查询方案全部开通 |
| P0 | 岗位、序列与职级 | 职位／职务名称、所属序列、职级、职责描述、任职要求。[职务查询（S05）](https://open.italent.cn/#/open-document?menu=document-center&id=7c19ab15-5aa0-4268-9f72-3984566aa911)、[职级查询（S06）](https://open.italent.cn/#/open-document?menu=document-center&id=e96a007d-7265-4e43-8b96-a051c9208269)；职位和序列按实际关联补充（S07、S08） | 有职级名称不代表已有岗位族行为锚点；职责和任职要求是否维护、是否为正式版本，需 HR 确认 |
| P1 | 历史绩效结果 | 绩效年度、周期、活动、被考核人、结果与等级等。[员工绩效查询（S09）](https://open.italent.cn/#/open-document?menu=document-center&id=99d8dea9-5218-4d51-8c51-1aca63023a18)、[活动查询（S10）](https://open.italent.cn/#/open-document?menu=document-center&id=7035ce6f-84fb-4204-9604-c56fcea39b8c)、[等级数据源（S11）](https://open.italent.cn/#/open-document?menu=document-center&id=a1f1b5a6-287f-4f88-97a7-878e349f6884) | 哪种状态才是正式发布结果；原等级含义、量表及规则版本能否追溯；只作受限历史档案 |
| P1 | 历史绩效评语 | 总评语、评价步骤、评价角色、评价人等。[总评评价信息（S12）](https://open.italent.cn/#/open-document?menu=document-center&id=0084671b-7c83-4462-9c0d-86802403cae6) | 区分不同步骤和评价人，不能混成一个最终评语；默认返回字段是否能满足白名单要求，见第 4.2 节 |
| P1 | 晋升历史 | 完整任职历史可提供时间、前后职级和异动类型（S03、S04） | 职级变化不一定是晋升；HR 要确认异动编码和跨序列规则，不能确认时只展示职级变更 |

### 2.1 最小字段及关联核对

以下为申请和映射时的重点字段，不替代需求白名单或租户字段表。字段大小写、类型、可空性及自定义编码以所用接口与实际元数据为准。

| 对象 | 重点字段或内容 | 核对要求 |
| --- | --- | --- |
| 组织 | `oId`、`code`、`name`、`pOIdOrgAdmin`、`startDate`、`stopDate`、`isCurrentRecord`、`status`、`personInCharge`、`hRBP` | 区分行政和业务组织维度；组织层级可由父子关系推导，不把一至五级名称当稳定主键 |
| 员工 | `userID`、`name`；按需取 `educationLevel`、`lastSchool`、`major`、`graduateDate` | 维护 QTalent 人员编号、北森 UserID 与工号的对照；不按姓名合并，不静默改变既有人员编号 |
| 任职 | `objectId`、`userID`、`jobNumber`、`oIdDepartment`、岗位／职级／序列关联、`pOIdEmpAdmin`、`pOIdEmpReserve2`、`isCharge`、人员状态、生效／失效时间、入职／转正日期、最后工作日、异动类型 | 保存当前与历史记录的区别；岗位、职级等关联的 OId、GUID、UserID 不混用；按状态和生效时间解释入离调转 |
| 自定义字段 | HRBP1／HRBP2、BUDDY、GitHub 等的实体、字段编码、类型、含义及维护情况 | 组织 `hRBP` 不能直接填两个人员 HRBP；无值、未授权和字段不存在分别核对；BUDDY 不直接作为导师授权 |
| 历史绩效与晋升 | 人员关联、周期／事件时间、原结果、原量表、评价来源、源记录 ID、源修改时间、同步批次 | 保留来源类型北森人事记录；结果修订保留历史，不能改写冻结依据；不把绩效材料标成完全客观事实 |

学历等只取[需求 v1.2 的人员字段白名单](../requirements/需求定稿-v1.2.md#391-人员基础字段白名单来源在职人员信息表s6)。北森也有教育、项目、培训等[员工子集查询（S13）](https://open.italent.cn/#/open-document?menu=document-center&id=01798fc7-5528-488b-afc6-dbe1bc18bde7)，但不为补几个字段开放全部子集，尤其不开放家庭等无关子集。

## 3. 核心人事 API 仍不能替代的数据

这里的缺口是相对于本次最小同步范围，不表示北森其他产品绝对没有相关能力。

| 缺口 | 补齐方式与责任 |
| --- | --- |
| XEngineer／Landing 等期次、学员名单、课题、导师和助教关系 | HR 在 QTalent 维护；BUDDY 不能直接当导师。开营名单和后续增补沿用管理者确认规则，确认前不扩大 HR 的跨期资料权限 |
| 关键事件的情境、行为、结果，个人贡献及原文定位 | 导师／HR 通过记录、文档和录音补充；保留段落、单元格或时间点，团队结果不复制为个人贡献 |
| 岗位族行为锚点、评价规则版本、人工评分、评分复核、象限校准和冻结快照 | QTalent 维护，由有权限的人确认；北森职级和岗位要求仅提供背景，不自动生成或替代评价标准 |
| 找人需求、本人意愿、可投入时间、实际交付与节点复盘 | 项目负责人、本人及 HR 补充；不能由职称或绩效等级推断 |
| QTalent 的业务角色、期次范围与查看权限 | QTalent 单独授权；北森组织、在职状态与汇报关系提供基础事实，不能直接变成业务角色授权 |

招聘面试评价、OKR、北森项目人力管理也有官方公开接口，但不属于本次最小同步范围。是否接入，先确认公司实际维护情况与具体用途，不能直接覆盖 QTalent 的人才项目和评价记录。

### 4.1 最小权限边界

- 连接器有同步权限，不代表所有 QTalent 用户可读同步数据。管理者按授权范围、HR 按已确认的期次名单、导师按所带学员访问；北森历史绩效与晋升不向导师开放。
- QTalent 系统管理员只管配置、同步任务、技术异常和审计，默认看不到人才数据；其账号不持有业务预设。业务角色和 HR 负责期次的授予或扩权仍按管理者确认规则执行。
- 默认不申请证件、出生日期、年龄、性别、联系方式、家庭、健康、银行卡、薪酬明细、考勤轨迹、合同社保，以及任何新增、修改、删除、审批或回写权限。
- 身份与任职歧义由 HR 负责人确认，技术异常由系统管理员处理；不靠猜测合并人员或更新授权，不为排错扩大管理员对原件和评价的可见范围。

### 4.2 绩效默认字段的限制

部分绩效接口会默认返回邮箱，`columns` 仅用于增加字段；总评接口还包含不可删除的默认字段，例如步骤分数，以及以姓名（邮箱）表示的评价人。具体可核对[按条件查询绩效（S18）](https://open.italent.cn/#/open-document?menu=document-center&id=6b6031e5-8cc9-4894-bab4-d426f20c7267)和总评接口 S12。

不能把传入 `columns` 当成脱敏措施。管理员需验证源端字段鉴权能否限制白名单外内容；不能限制时，暂缓该接口，改用可控制字段的查询或受控导出，不以先全量接入再丢弃字段代替最小权限。

组织员工接口中的 `columns` 也不收敛响应模型的字段结构，只控制相应列的值是否查询；字段鉴权是否生效要实测，不能只看请求中列出了哪些字段。

### 4.3 时效、历史与缺失口径

- 当前任职与最新任职分开核对：单任职查询的 `isGetLatestRecord` 默认可能取未来生效的最新主职；当前组织应按当前生效主职及公司已确认口径取数。多任职和历史接口的筛选能力不同，不直接复用单任职参数语义。
- 北森文档说明最后工作日当天仍在职，次日才转离职。HR 需确认实际状态生效时点、公司时区及同步允许延迟，验收项目要求的离职停用与调岗范围调整，不能简单把最后工作日当离职生效日。
- 任职历史、离职和删除记录不能被默认筛选漏掉；源组织接口的最新数据与有效期也不能直接证明完整历史组织版本已返回。历史不足时明确标注，不能推断没有变化。
- 按接口约束确定增量时间字段、滚动游标及分页；组织员工相关滚动接口文档要求相邻滚动调用间隔不超过 10 秒，并建议按不超过 90 天的窗口分段。失败重试与全量对账需在联调中验证，不把一次成功当持续同步已完成。
- 枚举翻译使用数据源接口，组织员工接口的 `enableTranslate` 功能已下线；不可依赖旧动态翻译参数。
- 未维护、未授权、字段不存在、成功无记录与同步失败分别记录；不能统一当成空数据、0 或没有发生过。

## 5. 联调验收与回执

以下全部是待联调项目；复选框只有在真实执行并留下证据后才能勾选，不能用文档核对、原型演示或 PR 合入代替。

- [ ] **最小权限**：已选接口及字段与申请表一致；未授权字段和人员不能读取，写入／审批／删除接口不可用；P1 默认字段限制验证通过。
- [ ] **人员关联**：稳定编号与工号对照正确；同名、换工号和重入职不会误合并；HRBP、BUDDY、自定义字段不错误地变成业务授权。
- [ ] **任职时间**：当前任职、未来生效任职、历史任职正确区分；主兼职、实习生、离职、停用和删除记录按批准范围处理。
- [ ] **撤权时效**：明确北森状态生效时点和同步延迟；实测离职停用账号、收回范围、调岗调整范围与会话／访问权限生效。
- [ ] **组织与历史**：组织停用、撤并和归属变化可对账；历史不足和歧义隔离，不猜测关联，不改写已冻结盘点的组织与人员快照。
- [ ] **历史绩效**：只接正式结果，保留原等级、周期、量表、评价来源、源记录 ID、源修改时间和同步批次；不同评价步骤不混合，后续修订不改写冻结依据。
- [ ] **用途隔离**：导师及系统管理员不能查看绩效；北森绩效与晋升不会进入评分、象限、值得关注、判断对照、找人证据或模型输入。
- [ ] **同步与错误**：首次全量、增量、游标中断后的重试、定期对账通过；空数据、未维护、无权限和同步失败分别呈现，留下批次记录及处理结果。

回执至少记录环境、连接器名称、执行时间、脱敏样本标识、预期与实际结果、证据位置、失败项及负责人；不记录 Key／Secret、Token 或真实人员原文。
