## 1. 新增的决定

| 编号 | 议题 | 决定 |
| --- | --- | --- |
| D-33 | 发展方向 | 人员档案新增「发展方向 / 目标通道」，通道取自人才发展大图（S2）「走得远」阶段；**本人意愿**与**管理判断**分开记录、分开呈现（见 3.15.1） |
| D-34 | 目标角色模板 | 找人可以从目标角色模板开始（产品架构师、FDE、商业架构师、业务负责人等），模板生成需求卡后仍可就地修改；沿用 v1.2 的需求卡、四种匹配状态和用人方案。**不做**继任梯队、长期候选储备和岗位编制（PRD 第 5.2 节边界不变）（见 3.15.2） |
| D-35 | 判断复盘 | 新增「判断复盘」：复盘的对象是**一次判断**（谁、在哪个阶段、用哪版标准、对谁的哪个维度给了什么结论），不是被评价的人。作为「复盘」的延伸实现，不新建独立子系统。覆盖两条判断链：XEngineer 入营选拔 → 训练营评审；社招面试 → 入职后表现（见 3.16） |
| D-36 | 复盘对照规则 | 跨阶段量表不同时，由 HR 为每条判断链确认一张带版本号的**维度与等级对应表**；对应表**只用于判断复盘的对照**，不把历史分数换算进档案维度分和象限。D-26、AC-38 不变 |
| D-37 | 双向对照 | 后一阶段的结果**不当作正确答案**。两个阶段都是判断，系统只呈现差异和双方证据；归因结论可以是「前段偏高」「后段偏严」或「情境不同，不可比」 |
| D-38 | 归因范围 | 「判断模型」指评价标准（维度定义、锚点、题目设计、定级规则），AI 建议分作为其中一个判断来源一起对照。归因分五类：评价标准 / 评价人 / 评价方式与信息不足 / 本人或环境变化 / 后段评价偏差；AI 只提出带证据的假设，归因由人确认 |
| D-39 | 评价人偏差的可见性 | HRBP 看全部评价人的偏差；每位评价人只看本人的偏差和对应案例；CEO 看按维度、阶段、标准版本的汇总和归因结论，**不看按评价人的数字**。不做评价人排行，不给准确率百分比；样本不到门槛只显示「样本不足」并列出案例。HR 总监的工作由 HRBP 视角承担，五类用户不变（D-18 不变） |
| D-40 | 修正闭环 | 归因生成改进动作（修订评价标准、调整评价人组合、评价人培训等），沿用「行动与复盘」；修订评价标准产生新版本（如 v1 → v2），之后的评价记录所用版本；下一批判断复盘按版本对比偏差是否缩小 |
| D-41 | 工作台按角色收敛 | CEO 工作台以一句话输入框（搜人、项目，或输入要做的事）为主入口；CEO 只保留需要本人确认的少量待办；HRBP 待办按类型分组、默认只展开最紧急的一组；原型的演示视角收进一个下拉（见 3.18） |

## 3. 对 v1.2 的变更与新增规则

### 3.15 关键岗位找人：发展方向与目标角色模板

#### 3.15.1 发展方向 / 目标通道

| 项 | 规则 |
| --- | --- |
| 通道清单 | 依据 S2「走得远」阶段：产品架构师、FDE（业务导向技术人才）、商业架构师，向业务负责人 / 销售负责人发展。清单由 HR 维护，属于规则版本的一部分。「未来 CEO 计划」按**发展项目**（项目类型：专项）处理，不作为通道（建议默认） |
| 本人意愿 | 员工在「我的」里填写或在自述中提到（如「想离客户近一点，试试售前」），按本人自述呈现，带时间；员工可以随时修改，旧记录保留 |
| 管理判断 | HRBP、部门负责人、CEO 填写「适合往哪个通道发展」，必须写依据（引用事件或观察）；按管理观察的可见性处理，员工和导师看不到 |
| 呈现 | 档案里两者并排、分开标注来源；没有记录显示「未知」，不当作「不想 / 不适合」；两者不一致时如实并列，不合成一个结论 |
| 不能做什么 | 不打分、不进入象限、不按通道排人；不从部门、职级、学历推断通道 |

#### 3.15.2 目标角色模板

| 项 | 规则 |
| --- | --- |
| 模板内容 | 名称、对应通道、典型职责、要求项（必须 / 加分，可带可替代的放宽要求）、相关维度、版本 |
| 维护 | HRBP 维护，CEO 可以修改；改动产生新版本，已生成的需求卡保留当时的模板版本 |
| 使用 | 在一句话输入框或「找人」里选择模板 → 生成需求卡 → 就地修改 → 候选人 → 用人方案。流程、匹配状态和确认规则沿用 v1.2 第 3.6.2 节 |
| 找业务负责人 | 常设岗位（如「新转化团队 owner」）仍以项目承载需求（D-19 不变）；模板解决「每次都从零写要求」的问题，不新建岗位对象 |
| 候选人卡 | 增加「发展方向」一行，按 3.15.1 分来源显示，作为要求匹配的参考事实；**不参与排序**，没有记录不算不满足 |
| 不做 | 继任梯队、长期候选储备、岗位编制与空缺管理 |

### 3.16 判断复盘（新增）

#### 3.16.1 对象与判断链

一次**判断** = 评价人 + 阶段 + 标准版本 + 被评价人 + 维度 + 结论（等级或分数）+ 原始评语。判断复盘把同一个人同一维度在前后两个阶段的判断放在一起对照。

| 判断链 | 前段判断 | 后段判断 / 证据 | 备注 |
| --- | --- | --- | --- |
| XEngineer | 入营选拔：面试筛选定级，按产品设计力、工程能力、内驱力定 S / A / B（建议默认，实际字段与等级定义见第 8 节） | 训练营评审：能力等级 S / A / B、作品分、个人分、导师评价（v1.2 第 3.9.2 节） | 两段量表一致时，对应表就是同名维度、同级对照 |
| 社招 | 面试评价：专业能力 / 潜力 / 沟通协作 / 管理能力 1–5 分、建议职级、综合评价（S9） | 入职后的已确认关键事件维度分；默认窗口为入职后 6 个月内（建议默认） | 量表不同，必须先有确认过的对应表 |

一个判断复盘按**批次**发起：XEngineer 按期次，社招按入职时间段（如 2026 H1 入职）。

#### 3.16.2 维度与等级对应表（复盘对照规则）

| 项 | 规则 |
| --- | --- |
| 内容 | 前段的每个维度对应后段的哪个维度，前段的每一级对应后段的哪一档；对应不了的标「不可比」 |
| 示例（社招，建议默认） | 面试「专业能力」↔ 专业度；面试「潜力」↔ 内生动力、智慧力、坚毅力；面试「沟通协作」「管理能力」↔ 领导力；面试 5 / 4 / 3 / 2 / 1 ↔ 后段同档。产品设计力、工程能力在 rubric-v1 里是专业度的方向标签（v1.2 第 3.7.2 节），对照时取带对应方向标签的专业度事件 |
| 后段取值 | 后段是事件维度分时，取对照窗口内该维度已确认分的均值所在档；同一维度至少 2 条来自不同事件的已确认分才参与对照，否则为「资料不足」（与象限落位门槛一致） |
| 确认与版本 | HRBP 起草、确认后生效，有版本号（如 `map-xe-v1`、`map-hire-v1`）；判断复盘记录所用的对应表版本，对应表改版后旧复盘不被重算 |
| 边界 | 对应表只在判断复盘里使用。历史分数仍不换算进档案维度分、不参与象限（AC-38 不变） |

#### 3.16.3 对照单元与差异状态

每个「人 × 维度」是一个对照单元，显示前后两段的评价人、标准版本、结论和原始证据（评语、事件引用）。差异状态只有五种：

| 状态 | 含义 |
| --- | --- |
| 一致 | 按对应表，前后落在同一档 |
| 前段偏高 | 前段高于后段，写明差几档（如「高一档」） |
| 前段偏低 | 前段低于后段，写明差几档 |
| 不可比 | 对应表里没有对应关系，或两段情境不同（由人标注并写理由） |
| 资料不足 | 后段证据不够（见 3.16.2），或前段没有该维度的结论 |

「不可比」「资料不足」不计入偏差，也不当作判断失误。后段证据明显更多时可以标注「后段证据更充分」，但不自动当作真值（D-37）。

#### 3.16.4 汇总视图

| 视图 | 内容 | 谁能看 |
| --- | --- | --- |
| 按维度 | 每个维度的一致 / 偏高 / 偏低 / 不可比 / 资料不足人数（写成「8 人中 6 人前段偏高」，不写百分比） | HRBP、CEO |
| 按阶段与标准版本 | 同一判断链不同期次、不同标准版本之间的对照，用于看修订是否有效 | HRBP、CEO |
| 按评价人 | 每位评价人的可对照案例数和偏差分布；案例少于门槛（建议默认 **5 个**）时只显示「样本不足」并列出案例 | HRBP 看全部；评价人本人只看自己；CEO 不可见 |
| 案例 | 单个对照单元的双方证据 | 有权查看该复盘的人；评价人本人只看自己参与的案例 |

不做评价人排行，不给准确率百分比，评价人列表按姓名排列（沿用 v1.2 第 3.8.4 节「不按分数排序」）。

#### 3.16.5 归因

1. **AI 提出假设。**AI 根据汇总和案例提出若干归因假设，每条必须引用证据（哪些案例、哪段评语、哪版标准），流光样式。示例：「内驱力 8 人中 6 人前段偏高；其中 5 人的入营面试记录只写了『有热情』，没有具体行为 → 可能是评价方式与信息不足」。
2. **人确认归因。**HRBP 从五类中选择（可多选），写一句理由，确认后落墨并署名、留版本。未确认的 AI 假设不能生成改进动作。

| 类别 | 判断依据举例 | 常见改进动作 |
| --- | --- | --- |
| 评价标准（含 AI 模型与规则版本） | 锚点含糊、题目考不到该维度、定级规则过宽；AI 建议分与后段的偏差集中在某版规则 | 修订锚点、题目或定级规则，产生新版本 |
| 评价人 | 某位评价人的偏差方向稳定且样本够；同一候选人不同评价人分歧大 | 调整评价人组合、评价人培训 |
| 评价方式与信息不足 | 前段评语缺少具体行为；面试时长或形式观察不到该维度 | 增加行为追问、作品或实操环节 |
| 本人或环境变化 | 后段任务、团队、资源或目标发生变化；本人状态变化有事实依据 | 不修正标准，记录情境；必要时转为跟踪或沟通 |
| 后段评价偏差 | 后段评价人口径偏严、评价证据少或存在冲突 | 后段评价校准、补充证据 |

3. **不写回被评价人。**判断复盘的结论只作用于评价体系，不改变被评价人的维度分、象限、档案版本和「值得聊一聊」信号；被评价人的档案里仍只有原来的历史事件。

#### 3.16.6 修正闭环

| 环节 | 规则 |
| --- | --- |
| 改进动作 | 从已确认的归因生成，类型：修订评价标准、调整评价人组合、评价人培训、补充评价方式、后段评价校准；沿用「行动与复盘」的状态、责任人、观察目标和复盘日期（PRD FR-12） |
| 评价标准版本 | 入营选拔、社招面试的评价标准纳入规则版本管理（如 `xe-select-v1` → `xe-select-v2`）；每条前段评价记录所用版本；旧记录保留原版本标记，不静默重算（沿用 v1.2 第 3.7.4 节第 5 条） |
| 下一批验证 | 下一次判断复盘按标准版本分组，对比各维度一致与偏差人数的变化；样本不足时只提示，不下「改进有效」的结论 |
| 演示 | 「上一期已复盘 → 修订为 v2 → 本期用 v2」用清楚标识的历史时间线演示，不在刚确认的动作后伪造已经发生的效果（沿用 PRD 第 15.3 节） |

### 3.18 工作台按角色收敛（修订 v1.2 D-32 与第 4.1 节模块 A）

| 角色 | 首屏 |
| --- | --- |
| CEO | 第一视觉重点是一句话输入框（搜人、项目，或输入要做的事），下方提供目标角色模板的快捷入口（如「找业务负责人」「找商业架构师」）；其后是「变化」（D-32 对 CEO 改为输入框之后的第一块内容）；待办只保留需要 CEO 本人确认的事项（如待确认的方案），其余折叠为「还有 N 件在推进」 |

## 9. 风险提示

- **小样本误判评价人。**一期只有几个人，按评价人的规律几乎没有统计意义，容易冤枉人。门槛、「样本不足」和「只列案例」是硬约束，不能为了演示效果放宽。
- **评价人趋中打分。**评价人知道会被对照后，可能都打中间档来「减少偏差」。汇总时同时显示前段等级的分布，等级过于集中时提示「区分度低」，作为归因参考，不作为评价人的分数。
- **后段被当作真值。**界面上前后两段必须对称呈现，「后段评价偏差」是正式归因类别，不能藏在二级菜单。
