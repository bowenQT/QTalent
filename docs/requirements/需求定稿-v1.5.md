## 1. 新增的决定

| 编号 | 议题 | 决定 |
| --- | --- | --- |
| D-51 | CEO 首页定位 | CEO 首页是「看人」的地方，不是流程处理台。四块调整为：**找人**、**值得关注**、**需要我看**、**我的关注**；「判断提醒」保留为次级入口。修订 D-42 |
| D-52 | 两个集合 | 「**值得关注**」是系统按规则列出的候选名单；「**我的关注**」是本人点「加关注」保存的人。两者可以重叠，人数分开写，不混用。CEO 与部门负责人可以加关注；被关注的人、导师 / 助教看不到 |
| D-53 | 推动的位置 | 推动保留（D-45、D-46 不变），入口从「值得关注」的每一行移到速览和人员档案；首页每行只留「加关注」和「查看依据」。发起推动时自动加入「我的关注」，推动的进展作为关注动态出现 |
| D-54 | 首页减少系统说明 | 首页不显示规则编号、规则版本和「按规则算出」「资料从无到有」等解释，这些放到速览的「为什么关注」与档案；每行最多两个标签；「已关注」「已推动」等状态用按钮文字或一行提示表达；「已经在做的事」只在 7 天内有新进展时显示一行 |
| D-55 | 速览 | 所有角色的工作台上，点人或项目先拉起速览（桌面右侧栏，手机底部弹层），30 秒内看到为什么值得关注、关键事实、能力线索和已经在做的事；想深入再打开详情页。速览与详情页用同一套权限 |
| D-56 | 人员档案层级 | 第一屏依次回答：为什么值得关注、发生过什么、有什么证据、判断有什么变化；能力谱和能力象限放在第二层；发展方向只写一两行 |
| D-57 | 部门负责人 | 工作台改为本团队范围内的 CEO 视角：找人与记一件事、本团队的「值得关注」（已核实）、我的关注、待办。推动仍只有 CEO 能发起。修订 v1.4 3.25 与第 8 节「部门负责人看不到值得关注」 |
| D-58 | 导师 / 助教 | 工作台以「我带的学员」为主线：观察 → 记录（SBI：情境、行为、影响）→ 在这件事里评维度分 → 推荐。评价只在事件里打维度分（1–5，对照行为锚点），不设脱离事件的阶段评分 |
| D-59 | 推荐方向 | 导师 / 助教、部门负责人和 HRBP 可以推荐某人适合一个目标角色（如 FDE），写理由并引用至少 2 件不同的已确认事件。HRBP 核实后，档案显示「推荐方向 · 推荐人 · 核实人」，同时作为一次提名（T2）进入「值得关注」。推荐不产生分数、不改变象限，也不改变找人候选人的排序和资格 |
| D-60 | 配色收敛 | 墨与纸承担绝大部分界面；只保留 AI 光蓝一个强调色；语义色只用于判断状态和错误，以小标记出现；朱印只用于正式确认、冻结和「需要你决定」的计数；象限四色只在象限视图里出现。活力放在 IP 形象、AI 流光与操作反馈上 |
| D-61 | 记录事件的附件 | 记一件事时可以附多个文件：PDF、Word、PPT、Excel、TXT / MD、音频和视频。解析后作为这件事的出处写进档案：文档定位到段落，PDF 和演示文稿定位到页，表格定位到单元格，音视频转写后定位到时间点。视频只转写音轨，不做画面理解；扫描版 PDF 识别不出文字时只作附件保存。修订 PRD v1.0 FR-03「PDF、视频不纳入本期」的限定 |

## 2. 反馈来源与理解

### 2.1 同事「CEO 界面需求 V2」

同事的核心判断是：v1.4 的 CEO 首页仍像 HRBP 的人才运营台。CEO 要的是发现、关注、看人、找人；推动是了解之后的可选动作，不是首页的主要任务。

| 意见 | 结论 | 对应 |
| --- | --- | --- |
| 值得关注保留为首页最大区域，轻量筛选、不突出颜色 | 采纳 | 3.26.1、3.32 |
| 「查看人员与证据」改为「查看依据」 | 采纳；点击拉起速览，不直接跳页 | 3.27 |
| 每行的「推动」改为「☆ 加关注」，其他动作放到详情 | 采纳；推动在速览和档案里发起 | D-53 |
| N1、T1 等内部标记和「资料从无到有、按规则算出」等系统解释从首页隐藏 | 采纳；放到速览的「为什么关注」和档案，仍可追溯到规则版本与来源 | D-54 |
| 灰色跟踪横条只在有新证据时显示一行 | 采纳；7 天内有新进展才显示 | D-54 |
| 「我推动的事项」改为「我的关注动态」，决策待办折叠 | 采纳：右栏改为「需要我看」（只放需要 CEO 本人决定的事）和「我的关注」；CEO 发起、仍在推进的事折叠在「需要我看」下面 | 3.26 |
| 判断提醒保留为次级入口 | 采纳；位置移到右栏最后 | 3.26.1 |
| 区分「值得关注」与「我的关注」两个集合 | 采纳 | D-52 |
| 左侧项目、批次等多个入口合并 | 采纳：CEO 视角下「项目」与「Landing 第三期」合并为「项目与批次」，侧栏不显示「最近」 | 3.26.4 |
| 新结构里单列一块「最近关键事件」 | 不采纳：沿用 D-50，在「值得关注」里用「按项目看」。单列一块会和值得关注、我的关注重叠，也容易退回动态流 | D-50 |
| 示意图里 CEO 首页的「待核验证据」标签 | 不采纳：未核实的线索对 CEO 不可见（D-44） | D-44 |
| 人员详情第一屏先回答为什么关注、发生过什么、有什么证据 | 采纳 | D-56 |
| 能力象限分两层：概览 → 详细维度 → 某项能力的历史评价与原始证据 | 采纳两层结构，维度按 rubric-v1（专业度、内生动力、智慧力、坚毅力、领导力、开放性）。示意图里专业能力下的「商业、设计、工程」与「工程」下的六个子项不在 rubric-v1 里，**待需求方给出定义与锚点**后再加 | 3.28、第 9 节 |
| 象限位置标清评价时间、模型版本和证据是否充分 | 已有：正式位置写校准批次、时间与确认人，参考位置写规则版本与落位缺口 | 不变 |
| 发展方向最多一两行，不自动判定能否成为负责人 | 采纳；示意中的「产品架构师 → 产品负责人」属于多级路径，来源未确认前不展示（D-49） | 3.28 |
| 前台只保留三类标签：关注原因、证据来源、能力线索；一行最多两个；颜色统一为白底灰标签 | 采纳 | D-54、3.32 |

### 2.2 导师 / 助教与业务负责人的工作重点

同事反馈：导师 / 助教和业务负责人的重点是观察人、记录人（SBI 描述）、评价（「判断力几分、内驱力几分」）和推荐（「适合做 FDE」）；业务负责人还需要一个本团队内的 CEO 视角。

| 意见 | 结论 | 对应 |
| --- | --- | --- |
| 工作台以观察和记录人为主 | 采纳：导师首页先列「我带的学员」，每人一键「记一件事」；进行中的任务和上传材料收到次要位置 | 3.30 |
| 记录用 SBI 描述 | 采纳：记录页与事件卡的三段改名为情境、行为、影响，与 SBI 一致；AI 整理时按这三段输出 | 3.30.2 |
| 评价「判断力几分、内驱力几分」 | 只在事件里评：给这件事体现的维度打 1–5 分，对照行为锚点。不设脱离事件的单独评分（产品不变量「分数只有关键事件的维度分」不变）。「判断力」「推动力」是挂在维度下的观察主题，不改维度名 | 3.30.3 |
| 推荐「适合做 FDE」 | 新增「推荐方向」，核实后进档案和值得关注 | D-59、3.31 |
| 业务负责人有本团队内的 CEO 视角 | 采纳 | D-57、3.29 |

### 2.3 速览与配色（产品负责人要求）

| 要求 | 结论 | 对应 |
| --- | --- | --- |
| 从首页下钻到二级页面，明细与「为什么值得关注」之间有信息和逻辑断层 | 加速览：点人或项目先看「为什么关注 → 关键事实 → 能力线索 → 已经在做的事」，与首页那一行的原因直接衔接；想深入再进详情 | D-55、3.27 |
| 各角色工作台都能快速了解人和项目 | 速览是一个共用组件，按权限裁剪内容，首页、待办、学员列表、按项目看都可以拉起 | 3.27.1 |
| 整体颜色太多，要收敛，但不能失去活力和灵动 | 一个强调色 + 墨与纸；语义色只做小标记；头像不再逐人着色；活力留在 IP 形象、AI 流光和操作反馈上 | D-60、3.32 |
| 「去判断复盘」「全部」这类文字链接是蓝色下划线，看起来像浏览器默认样式 | 文字链接改为墨色细下划线，悬停加深；光蓝只代表 AI | 3.32 |
| 记录关键事件时不能上传附件 | 支持多附件，格式覆盖 PDF、PPT、文档、表格、音频和视频，解析后作为出处保存 | D-61、3.34 |

## 3. 对 v1.4 的变更与新增规则

### 3.26 CEO 首页（修订 v1.4 3.19）

#### 3.26.1 结构

| 块 | 内容 | 规则 |
| --- | --- | --- |
| 找人 | 不变（v1.4 3.19.1） | — |
| 值得关注 | 类别筛选（全部 / 新发现 / 突出表现 / 需要介入，带人数）、按人看 / 按项目看、最近 4 条、查看全部。每一行：头像、姓名、部门与职位、关注原因标签、一句话原因与证据角标、操作「☆ 加关注」（已关注时显示「已关注」）和「查看依据」 | 不显示规则编号、规则版本、「按规则算出」等解释；每行最多两个标签；7 天内有新进展时，在原因下方显示一行（如「已推动：进一步了解 · 苏晚 · 10-22 已约 10-28 沟通」）。点姓名、头像或「查看依据」拉起速览 |
| 需要我看 | 只放需要 CEO 本人决定的事：待确认的用人方案和组织调整方案，一行一条 | 1440 × 900 首屏可见；没有时写「暂时没有要你决定的事」。下面折叠一行「你发起的 N 件在推进」，展开后是找人需求、推动和复核请求，各自写负责人、状态和最近进展；完成 7 天内的显示在「近 7 天有结果」里 |
| 我的关注 | 标题写人数；下面是关注动态，按时间从新到旧，最近 5 条；「关注名单」打开完整名单 | 见 3.26.2；一个人都没关注时，说明「在值得关注或速览里点加关注，之后他们的新进展会出现在这里」 |
| 判断提醒 | 不变（v1.4 3.22），放在右栏最后 | — |

桌面端：找人横跨全宽；其下左侧为「值得关注」，右侧依次为「需要我看」「我的关注」「判断提醒」。手机端顺序：找人 → 需要我看 → 我的关注 → 值得关注 → 判断提醒。

#### 3.26.2 我的关注

| 项 | 规则 |
| --- | --- |
| 加关注 / 取消关注 | 在「值得关注」的行、速览和人员档案里都可以操作；取消关注有撤销。关注只是个人的观察名单，不产生分数，不改变档案、象限和状态信号 |
| 关注名单 | 人、关注日期、最近一条进展；可以取消关注 |
| 动态的来源 | 关注之后发生、本人有权限看到的：已确认的关键事件（AI 建议分未确认的不算）、新命中的值得关注、推动的进展与结果、重点跟踪的更新、行动的状态、核实后的推荐方向。每条写人、事、日期和来源 |
| 不显示 | 未核实的 AI 线索与提名、分数与均值、象限位置变化 |
| 一段时间没有动态 | 不是负面信息，不提示「没有进展」 |
| 推动与关注 | 发起推动时自动加入关注；推动结束后关注保留，可以手动取消 |
| 可见性 | 关注名单只对本人可见：被关注的人、导师 / 助教、其他角色都看不到某人被谁关注 |

#### 3.26.3 推动的入口（修订 v1.4 3.21.2「发起」）

- CEO 从速览或人员档案发起推动；首页的行内不再有推动按钮。四种动作、负责人、依据、状态、取消与结果回流都不变。
- 发起依据仍是那条「值得关注」的规则、原因和证据（v1.4 3.21.2）；不在值得关注里的人，依据为空，发起时可以写一句说明。

#### 3.26.4 CEO 外壳（补充 v1.4 3.19.3）

| 位置 | CEO 视角 |
| --- | --- |
| 侧栏导航 | 「项目」与「Landing 第三期」合并为「项目与批次」；不显示「最近」；「行动与复盘」保留 |

### 3.27 速览（新增）

#### 3.27.1 什么时候拉起

- 工作台首页（桌面与手机）：值得关注里的人名、头像和「查看依据」，「按项目看」里的项目或批次名，我的关注的动态与名单，导师的学员列表与「我的推荐」；待办里「CEO 请你」和「待核实线索」两类带「看速览」按钮（手机工作台和待办页里叫「速览」，其余待办本身就链接到要办的页面）。
- 按住 ⌘ / Ctrl 点击，或在速览里点「打开档案」「打开项目」，进入详情页。
- 速览不是新页面，也不新增权限面：内容与详情页用同一套权限过滤。

#### 3.27.2 人的速览

| 段落 | 内容 | 谁能看到 |
| --- | --- | --- |
| 头部 | 头像、姓名、部门与职位、在职时长；「☆ 加关注 / 已关注」；「打开档案」 | 加关注：CEO、部门负责人（本团队） |
| 为什么值得关注 | 关注原因（新发现 / 突出表现 / 需要介入）和一句话原因；来源（按规则得出，或「谁提名 · 谁核实」）；规则编号与版本放在这一段的末尾，供追溯 | 能看「值得关注」的角色，且这个人在名单里 |
| 关键事实 | 最近 3 件已确认的关键事件：日期、一句话、所在项目、记录人、原文角标；「查看全部」进档案时间线 | 有权限看这些事件的角色（导师看不到管理观察） |
| 能力线索 | 有证据的维度，每个写「几件事」和最高一档行为锚点的说法（如「内生动力 · 2 件事 · 有难度的情境下主动表现，并有可见结果」）；没有证据的维度合并写「其余维度资料不足」，不当作负面 | 能看维度分的角色；员工看不到 |
| 推荐方向 | 已核实的推荐：目标角色、推荐人、核实人、理由 | CEO、HRBP、部门负责人（本团队）；推荐人能看到自己那条 |
| 已经在做的事 | 重点跟踪、行动、CEO 推动（仅 CEO 与被指派的负责人看到推动） | 与 v1.4 3.20.2 相同 |
| 底部操作 | 打开档案；推动（仅 CEO）；记一件事；推荐（导师 / 助教、负责人、HRBP） | 按各自权限 |

不显示：分数均值、百分比、排名；象限位置只在详情页的第二层出现，速览里不放。

#### 3.27.3 项目的速览

| 段落 | 内容 |
| --- | --- |
| 头部 | 项目或批次名、类型、状态、周期、owner；「打开项目」 |
| 目标 | 一句话目标 |
| 相关的人 | 本人可见的「值得关注」里依据事件在这个项目的人，写一句原因；导师只看到所带学员 |
| 找人 | 有权限时显示找人需求与用人方案的状态 |
| 最近的关键事件 | 最近 3 件，写日期、人和一句话 |

#### 3.27.4 交互

| 项 | 规则 |
| --- | --- |
| 桌面 | 从右侧拉出约 420px 的侧栏，不遮住左侧列表；侧栏开着时点另一个人，内容直接切换 |
| 手机 | 底部弹层，最高到屏幕的 85%，可以下滑或点关闭 |
| 关闭 | Esc、关闭按钮；焦点回到拉起它的那个元素 |
| 动效 | 滑入不超过 320ms，减少动态效果时直接出现 |
| 30 秒原则 | 一屏内能读完为什么关注、关键事实和能力线索；长内容在详情页 |

### 3.28 人员档案层级（修订 v1.2 档案页结构）

| 顺序 | 内容 |
| --- | --- |
| 第一屏 | 头部（加关注、推动、记一件事）→ **为什么值得关注**（能看值得关注且此人在名单里时）→ **关键事件与证据**（最近 3 件，带原文角标，「查看全部」到时间线）→ **判断变化**（变化标记、档案版本对比） |
| 第二层 | 个人能力谱（详细维度，点一行看事件与历史评价）；能力象限（正式位置、参考位置，标清校准时间、确认人与规则版本） |
| 轻量 | 发展方向：一两行，含本人意愿、管理判断和已核实的推荐方向；不判定能否成为负责人 |
| 其余 | 时间线、值得聊一聊、重点跟踪、参与的项目、本人纠错，位置与规则不变 |

导师、员工视角按原有权限裁剪（导师看不到象限、变化、管理观察；员工看不到分数和象限）。

### 3.29 部门负责人工作台（修订 v1.4 3.19.2 与 AC-61 中负责人一行）

| 块 | 内容 |
| --- | --- |
| 一句话输入 | 找人和记一件事都可以，提示两者都讲 |
| 值得关注（本团队） | 与 CEO 相同的规则与呈现，范围是本人完整查看范围内的人（本部门）；本人担任 owner 的项目成员不在内 |
| 变化 | 保留，放在值得关注之后 |
| 待办 | 不变，含「CEO 请你」 |
| 我的关注 | 与 CEO 相同，只能关注本团队的人 |
| 我的推荐 | 与导师相同：本人提交的推荐与处理状态；手机端放在首页我的关注之后 |
| 进行中的任务、上传材料 | 收进「材料与任务」，默认折叠 |

推动仍只有 CEO 能发起；负责人对本团队的人用重点跟踪、行动和推荐。

### 3.30 导师 / 助教工作台（修订 v1.3 3.18 中导师一行）

#### 3.30.1 结构

| 块 | 内容 |
| --- | --- |
| 一句话输入 | 提示按 SBI 讲：在什么情境下、做了什么、带来什么影响 |
| 我带的学员 | 每人一行：议题、本周记了几件事、最近一件的日期；操作「记一件事」「推荐」；点姓名拉起速览 |
| 待办 | 不变：待核对、跟踪到期、对人复盘 |
| 我的推荐 | 本人提交的推荐与处理状态（HRBP 核实中 / 已核实 / 不采纳及理由） |
| 进行中的任务、上传材料 | 收进「材料与任务」，默认折叠 |

「本周还没记」只是提醒记录人，不出现在学员的档案里，也不当作学员的负面信息。

#### 3.30.2 SBI 记录

- 记录页、事件卡的三段统一叫**情境**（Situation）、**行为**（Behavior）、**影响**（Impact）。原「背景」「结果」两个叫法一并替换。
- AI 整理一句话时按这三段输出；分数只看「行为」段里本人的做法。

#### 3.30.3 评价

- 在事件里给体现出的维度打 1–5 分，对照行为锚点；评分人、规则版本和原文引用照旧。
- 不提供「判断力几分」这类脱离事件的评分入口。导师想表达对一个人的整体看法时，用「推荐方向」或在事件里写评语。

### 3.31 推荐方向（新增，规则版本 `watch-v2`）

| 项 | 规则 |
| --- | --- |
| 谁能推荐 | 导师 / 助教（所带学员）、部门负责人（本团队）、HRBP（归属人员） |
| 推荐什么 | 一个目标角色（取目标角色模板，如找 FDE、找产品架构师），一句理由，引用至少 2 件来自不同事件的已确认记录 |
| 核实 | 进入 HRBP 待办「待核实」；HRBP 可以核实或不采纳（不采纳要写理由）。HRBP 本人提交的推荐直接视为已核实，署本人 |
| 核实之后 | 档案的发展方向显示「推荐方向 · 角色 · 推荐人 · 核实人」；同时作为提名（T2）进入「值得关注」，一句话原因写「某某推荐：适合做 FDE」 |
| 不改变 | 维度分、象限、档案版本、状态信号；找人候选人的排序与候选资格 |
| 推荐人看到 | 自己推荐的处理状态；导师 / 助教看不到「值得关注」本身，也看不到推荐是否进入了值得关注 |
| 规则版本 | T2 的来源从「负责人或 HRBP 提名」扩为「负责人、导师 / 助教或 HRBP 的提名与推荐」，规则版本升为 `watch-v2`；其余规则与 watch-v1 相同 |

### 3.32 配色收敛（修订设计系统色彩规则）

| 颜色 | 用在哪里 | 不再用在哪里 |
| --- | --- | --- |
| 墨与纸（`--ink*`、`--paper`、`--sheet`、`--line`） | 正文、标签、按钮、计数、状态、头像底色 | — |

### 3.34 记录关键事件的附件（新增，修订 PRD v1.0 FR-03）

| 项 | 规则 |
| --- | --- |
| 入口 | 桌面「记录关键事件」输入区的附件按钮，或把文件拖进记录卡片；手机「一句话记录」的「添加附件」。一次可以选多个 |
| 格式 | PDF、Word（DOC / DOCX）、PPT（PPT / PPTX）、Excel（XLS / XLSX / CSV）、TXT / MD、音频（MP3 / M4A / WAV / AAC）、视频（MP4 / MOV / WEBM / M4V）。工作台「上传材料」用同一口径 |
| 数量与大小 | 一条记录最多 10 个附件，单个不超过 2 GB；超出的不加入并说明原因 |
| 状态 | 每个附件显示上传中、解析中（音视频为转写中）、已解析或失败；失败写明原因和能做什么，例如「不支持 .zip 格式，可以上传 …」。保存前可以移除 |
| 定位 | 文档到段落，PDF 和演示文稿到页，表格到单元格，音视频转写后到时间点；视频只用音轨。扫描版 PDF 识别不出文字时标「未识别出文字」，只作附件保存，在事件上显示为附件但不能定位到具体内容 |
| 保存 | 还有附件在上传或解析时不能保存，提示还剩几个；已解析的附件和原话一起作为这件事的出处写进档案，在事件卡上是引用角标，可以回到具体位置 |
| 保留上下文 | 「改原话」和撤销保存回到录入页时，已解析的附件保留 |
| 权限 | 附件跟随所属事件的可见范围；管理受限的事件，其附件同样受限 |

原型不读取真实文件内容，只演示状态流转和出处呈现：引用位置（第几页、第几段、哪个单元格、哪个时间段）按文件名生成示意，原文处标「原型示意」；文件名含「扫描」的 PDF 演示识别不出文字的情形。

## 10. 风险提示

- **关注变成隐性标签。**「CEO 关注过」天然有分量。关注只对本人可见，不进档案、不影响任何判断；关注动态不显示分数，没有动态也不提示「没有进展」。
- **推荐滑向内定。**推荐必须引用两件不同的已确认事件并经 HRBP 核实，不改变找人排序；推荐的是「值得考虑的方向」，不是任用结论。
- **速览替代详情。**速览只放 30 秒能读完的事实，结论性的内容（象限、完整评价历史）留在详情页，避免只看速览就下判断。
- **配色收敛损失活力。**只收敛「信息色」，不收敛 IP 形象、流光和操作反馈；改完后按 1440 宽与 375 宽实看首页、档案和设计系统。
