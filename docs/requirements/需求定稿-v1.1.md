## 2. 产品体验原则（设计系统与原型共同遵守）

1. **意图优先。**用户先用一句话、语音或一段材料说明要做什么，系统围绕这个任务生成活文档，而不是让用户先在导航里找页面、填表。
2. **来源即视觉语言。**原始事实、本人自述、管理观察、AI 推断、人工结论分别用不同的视觉材质表示：
   - AI 生成的内容有淡淡的流光底，表示"建议中"；
   - 人编辑或确认后"落墨"，变成实色正文，并带上确认人；
   - 引用以角标呈现，悬停时展开原文片段，点击可跳到文档段落或录音时间点。
3. **过程可见，但不打扰。**AI 的步骤（读取需求 → 检索授权范围内的 38 人 → Jev 核对 4 项要求）显示为一行可折叠的进度轨迹；流式结果逐块长出来，没有转圈等待。
4. **直接操作优先于对话。**能点、拖、改的地方不要求用户输入一段话；对话只用于发起任务和追问。
5. **不做无依据的分数。**不出现综合人才分、能力百分比、雷达图或九宫格；只呈现"支持 / 不支持 / 资料不足 / 证据冲突"和对应证据（沿用 PRD 第 9.3 节）。
6. **人的责任清晰可见。**草稿和正式版本在视觉上明确区分；确认是一个有分量的动作（冻结快照），撤销随处可用。

## 3. 对 PRD v1.0 的变更

### 3.1 FR-04 / 第 11 节：移动端录音（扩大范围）

v1.0 写的是"长会议优先上传已录好的文件，手机长时间录制与实时转写不进一期"。现改为对标「得到」：

| 环节 | 要求 |
| --- | --- |
| 模式选择 | 底部弹出的录音面板，选择「观察速记」「多人会议」「上传录音文件」；显示单次时长上限（具体数值以联调为准）；语言选择 |
| 录制中 | 实时转写逐句出现，未定稿的字用浅色显示；底部工具：**打标记**（标记关键片段）、**随手记**（插入文字备注）、**@某人**（在当前时间点关联人员，替代得到的"拍重点"）；暂停 / 完成；可最小化为悬浮条后继续浏览其他页面 |
| 完成后 | 进入异步处理状态，由 IP 形象提示"转写与整理中，可以直接返回"；任务在工作台持续可见 |
| 结果：人才纪要 | 对应得到的"图文纪要"：会议摘要、涉及人员、新增证据卡（背景—行为—结果—来源时间点）、**待核对**（如"小王"指谁）；另一个标签页是带说话人与时间点的文字记录；顶部可播放原录音，点击证据跳到对应时间点 |
| 追问 | 底部输入框支持"按住说话 / 轻点输入"，并提供推荐追问（如"谁在这次会议里展现了推动力？""有要跟进的事吗？"） |

开发期约束（不影响原型）：
- 实时转写接通义听悟的实时接口，离线长音频继续走 v1.0 的异步链路；
- 浏览器在锁屏或切到后台时会暂停页面和麦克风（iOS Safari 尤其明显），这是 Web 平台本身的限制，与是否在企业微信内无关。界面要提示保持亮屏，并尽量调用屏幕常亮接口；录音分段上传落盘，中断后可以续录，已上传的分段不丢失；
- 具体时长上限、格式和并发在联调后确定，并展示在面板上。

### 3.2 新增：Landing 批次与对人复盘（承接 CEO 场景）

依据 S3：Landing 面向所有七牛新人，为期 4 周进组做项目，每周对事复盘、每两周对人复盘，结营时评估，形成"第一份判断力档案"。

- 不新建独立子系统，作为**重点跟踪的一个批次模板**实现：一个批次 = 期次 + 新人名单 + 议题/项目 + 导师 + 复盘节奏。
- 双周对人复盘是一份活文档：自动带入两周内的观察、录音证据和导师记录，按"判断力、推动力"等观察问题组织；导师和 HR 补充后确认。
- 结营时，每位新人的复盘汇总进人员档案，作为"第一份档案"，后续项目找 owner 和盘点都可以引用。

### 3.3 FR-15 / 第 11.4 节：入口改为纯 H5

- 取消企业微信作为主入口：手机端以 iOS Safari、Android Chrome 为目标浏览器，桌面以 Chrome / Safari / Edge 为目标浏览器。
- 登录沿用预置独立账号（v1.0 本就不依赖企业微信 SSO）。
- 麦克风访问要求 HTTPS 部署；首次录音需要处理浏览器的授权弹窗，权限被拒时退回文字输入和文件上传（沿用 FR-15）。
- 可以加入"添加到主屏幕"（PWA），提供接近 App 的入口；不作为必做项。
- 相应验收调整：AC-08、AC-26 中的"企业微信"改为"手机浏览器"；PRD O-06 关闭。

### 3.4 优先级说明

v1.0 的 16 个功能项、30 条验收用例保留不动。三天内的开发裁剪在原型定稿后另做决定，本文不预先删减。

## 4. 原型范围与页面清单

### 4.1 桌面端

| 模块 | 页面 / 视图 | 必须可交互的关键动作 |
| --- | --- | --- |
| A. 工作台 + 记录 + 归属核对 | 工作台（一句话输入框、待核对、待跟进、进行中的任务）；全局 ⌘K；观察记录；材料上传与处理状态；会议人才纪要 | 一句话记录 → 解析出人员和事件 → 保存后可撤销；上传会议 → 状态流转；"小王指谁"一次选择 → 证据飞入对应档案 |
| B. 人员档案 + 重点跟踪 | 人才列表；人员档案（摘要、时间线、证据卡、标签与判断、跟踪事项）；Landing 批次与双周对人复盘 | 展开引用原文；修订标签（看到前后值与修订人）；设为重点跟踪并填观察问题；完成一次双周复盘 |
| C. 项目找人 / 找 owner | 找人活文档：需求卡 → 候选人 → 对比 → 项目用人方案 | 一句话生成需求卡并就地修改 → 候选人随之重排；手动加人；把候选人拖进方案的角色槽位；区分"未知"与"不满足" |
| D. 盘点 → 方案 → 确认 → 复盘 | 盘点批次（范围、截止时间、人员清单、资料缺口）；组织调整方案；版本确认；行动与复盘 | 固定范围；逐人写结论；生成调整草案；确认当前版本（冻结快照）；改版后对比差异；从方案进入复盘并对照当初判断 |
| 视角切换（仅原型） | 右上角切换 HR / 经理 / 管理决策者 / 员工 | 员工视角只看到本人允许可见的内容；无 confirm_plan 权限的经理点"确认"会被拒绝。此切换仅用于原型演示，不代表权限实现 |

### 4.2 手机端

| 流程 | 内容 |
| --- | --- |
| 录音 | 第 3.1 节的完整链路：模式选择 → 实时转写 → 完成 → 处理中 → 人才纪要 → 追问 |
| 快速记录 | 一句话 / 按住说话，保存一条观察 |
| 看人 | 人员档案的单列版本，证据卡纵向排列 |
| 待核对 | 逐条处理归属歧义 |
| 确认方案 | 查看方案摘要和差异，确认当前版本 |

### 4.3 交互巧思清单（原型需实现）

- **落墨**：AI 草稿被人确认时，流光底收拢成实色正文，并在页边落下确认人的小签名。
- **引用角标**：悬停展开原文片段；录音来源可以就地播放那 10 秒。
- **证据飞入**：核对归属后，证据卡沿弧线飞向对应人员头像，计数随之 +1。
- **需求即时重排**：修改需求卡中的一项要求，候选人列表做位置过渡动画重排，变化的证据高亮。
- **拖入槽位**：把候选人拖进方案的角色槽位，槽位吸附并显示该角色对应的证据缺口。
- **冻结快照**：确认版本时，文档做一次"压印"动效，生成版本号；之后的修改自动进入新草稿。
- **差异视图**：新证据进入或方案改版时，用行内差异标出新增和变化。
- **撤销 Toast**：直接保存的记录在底部显示 5 秒倒计时撤销。
- **IP 形象状态**：倾听、检索、思考、完成、需要你确认、出错，各有对应的微动画，出现在输入框、处理状态和空状态处。

## 6. 设计系统交付清单

- **Tokens**：颜色（中性色阶、智能强调色、来源材质、状态色）、字体与字号阶梯（中文优先）、间距、圆角、阴影/层级、动效曲线与时长。
- **来源材质规范**：事实 / 自述 / 观察 / AI 推断 / 人工结论的视觉区分，以及判断状态（支持 / 不支持 / 资料不足 / 冲突）。
- **组件**：输入框（文字 / 语音 / 附件 / 斜杠命令）、Agent 进度轨迹、活文档块、证据卡、引用角标与原文浮层、人员行与人员卡、候选卡、方案角色槽位、版本条与差异视图、待核对卡、状态徽标、撤销 Toast、录音面板与悬浮录音条、音频播放器、空状态 / 加载 / 失败。
- **IP 形象**：2–3 个概念候选供选择，选定后输出 6 种状态的动画规范；原型阶段允许使用矢量占位。

## 8. 风险提示

- **工作量**：一人 + AI 在原型之后的剩余时间内完成 v1.0 全部验收用例风险很高，建议原型定稿时一并决定开发裁剪。
- **录音扩范围**：实时转写和浏览器锁屏/后台中断录音，是本轮新增的最大技术不确定项，应在开发首日优先联调。
- **演示真实性**：原型的 AI 结果是脚本化的。比赛时如仍有预置结果，需要按 PRD 第 15.3 节如实标注。
