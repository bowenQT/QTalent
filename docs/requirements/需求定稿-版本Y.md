## 1. 定位与差异总览

版本 Y 用于和版本 X 对比评审，两版共用评审导览页，互不影响。和版本 X 相比：

| 方面 | 版本 X | 版本 Y |
| --- | --- | --- |
| 角色 | CEO、HRBP、部门负责人、导师 / 助教、员工 | 管理者、HR、导师（DY-01）；另有只管系统配置的系统管理员（DY-13） |
| 演示数据 | Landing 第三期等虚构演示人员 | XEngineer 第六期的学员、课题、导师与助教（DY-02） |
| 管理者首页 | 找人、值得关注、我推动的事项、判断提醒（v1.4～v1.5） | 判断提醒只占一行；值得关注的人和项目分开；去掉推动与审批（DY-04） |
| 复盘 | 行动与复盘：逐条行动的任用后复盘 | 人才项目的关键节点复盘（DY-07） |
| 判断对照 | 侧栏单列 | 归入「人才评价规则」的第二个页签（DY-06） |
| 手机端 | 五种角色 | 只给导师（DY-11） |
| 录音 | 手机端录音 | 手机端之外，HR 和导师也可以在桌面浏览器实时录音（DY-16） |
| 视觉 | 「光与墨」设计系统 | 浅灰底、白卡细边、石板蓝强调，保留小犇与 AI 流光动效（DY-03） |

## 2. 决定

| 编号 | 议题 | 决定 |
| --- | --- | --- |
| DY-01 | 角色 | 三种角色：**管理者**（公司层：看人、找人，确认规则与方案）、**HR**（负责人才项目：XEngineer、Landing、校招、黑客松）、**导师**（看所带学员，做对人复盘）。助教的评分和意见以评价人身份出现在导师评价与评分复核里，不单设登录视角。部门负责人、员工视角不在版本 Y 范围内 |
| DY-02 | 演示数据 | 人员、课题、事件和评语来自 XEngineer 第六期（93 名学员、19 个课题组），只把人名和项目名换成化名并标「演示」；不含健康、家庭、性格、行踪与排名类内容。Landing 第四期、2027 届校招提前批、夏季黑客松为少量演示数据。这是版本 Y 的前提，仅适用于 `prototype/y/` |
| DY-03 | 视觉 | 浅灰底、白卡细边、石板蓝强调色；小犇 IP、AI 流光与落墨动效保留。颜色、字体与组件以版本 Y 设计系统为准 |
| DY-04 | 管理者首页 | 从上到下：判断提醒（一行告知哪一期前后判断对不上、谁在处理，以及待确认的规则修订）、找人、值得关注的人、值得关注的项目、我的关注。不放「我推动的事项」，不在首页审批组织调整方案，不出现由管理者「推动」的行动 |
| DY-05 | 职责分工 | 写管理判断、采纳 AI 摘要、校准、处理「值得聊一聊」、收录标签、起草和确认留用与落位方案由 HR 做；管理者只读这些内容，确认人才评价规则的修订和找人方案。方案确认后同时确认这次盘点并冻结；之后的调整在下一次盘点里做。发起盘点时，这个团队还有没确认的盘点就接着做那一批，都确认了才新建一批，对比基准取最近一次盘点 |
| DY-06 | 判断对照 | 界面称「判断对照」，归在「人才评价规则」下作为第二个页签（规则 / 判断对照）；不能看汇总、但做过评价的人保留「我的判断对照」入口。判断提醒只按前段给了明确判断（最高或最低一档）的人计算不一致：后段结论和它不同才算；前段在中间档的人单独列出后段结论的分布，不算不一致。首页提醒和对照页用同一口径。对照引用回到原始表格里这个人所在的真实行 |
| DY-07 | 人才项目与关键节点复盘 | 见第 4 节。复盘按人才项目的关键节点回看一件事做得怎么样，不逐人复盘；HR 署名即生效，管理者只读（2026-10-25 确认） |
| DY-08 | 对人复盘的评价 | 每一维的评价和分数一样，HR 和所带导师都可以采用、改写、修正 AI 草拟；AI 草拟标明「仅供参考」，保存后署名，旧版本保留 |
| DY-09 | 评分复核 | 原「校准队列」。三类进入条件：两位评价人打分差 2 分以上；改了 AI 的分还没写理由；冻结后的新事件让象限位置变了。最后一类可以去象限校准重新确认，也可以写理由保持校准过的位置（理由进档案，可撤销）。重新校准指向覆盖这个人、还没确认、团队也没冻结的盘点；没有时引导发起新的盘点 |
| DY-10 | 导航与命名 | 见第 3 节 |
| DY-11 | 手机端 | 只给导师：录音、一句话记录、导师评价（对人复盘）、待核对、所带学员与档案。复盘时补说的事件按当天记日期，并归入这次复盘 |
| DY-12 | 人才评价规则 | 沿用 v1.6 第 3.35 节，确认发布的角色由 CEO 改为管理者，起草由 HR 做。原评分人可以按新版本复核本人评分，复核后的校准与取数一致。修订建议记下针对的锚点集合和版本。**例外：入营选拔标准**（前段评价标准里的 XEngineer 入营选拔标准）不按 3.35 的生效点生效：只能从判断对照里 HR 已确认、归因含「评价标准」的结论起草，规则页不直接起草；管理者可以确认发布或退回；确认发布即生效，成为之后新建期次的默认版本，不排期，也不随盘点批次生效。期次建立时绑定当时的版本，之后不改版；这一期的选拔记录和判断对照按期次读取所用版本。判断对照生成的「修订入营选拔标准」改进动作，状态从带去的那份修订推出来（起草中 → 待确认 → 已生效），不另存，也不能手工改。前段评价标准里的对应表这一期仍只读 |
| DY-13 | 系统管理员 | 单设系统管理员视角，只管账号与权限、北森同步、集成配置和审计日志，看不到任何人员的人才数据：侧栏只有「系统管理」，打开业务页面时整页拦下，标题和面包屑也不带出人名、项目名，不能搜人。原型的系统管理页只示意这四块的结构，数据为演示；北森同步、审计等的实现范围与阶段见[架构提案](../proposals/2026-10-25-y-architecture-phases.md) 4.3、4.4 |
| DY-14 | 授权变更 | 系统管理员账号不持有业务角色；授予或扩大管理者、HR 的权限和 HR 负责的期次，由系统管理员发起、管理者确认后生效。HR 负责的期次里有哪些学员由 HR 在人才项目里维护：只能加北森在职人员，开营时整份名单经管理者确认后锁定，之后逐人增补也要管理者确认，确认前 HR 只看此人在本期的资料。原型只在系统管理页写明这条规则 |
| DY-15 | 人才列表与速览 | 人才页的人员列表（导师为「所带学员」）点一行先拉起速览，与工作台同一套：桌面在右侧、不挡住操作，Esc、关闭按钮、点抽屉外或再点同一行都能关闭，关闭后焦点回到该行；⌘ / Ctrl / Shift 点击照常打开人员档案；键盘 Tab 到行后 Enter 拉起速览，带修饰键的 Enter 照常进档案。列表按团队名的中文拼音排列，组内按姓名拼音，管理者、HR、导师相同；不按分数、关注或推荐排序。「值得聊一聊」页签的行仍直接进档案 |
| DY-16 | 桌面录音 | HR 和导师可以在桌面浏览器实时录音；管理者和系统管理员没有入口，直接打开录音页时整页拦下。入口在工作台（HR 的「上传材料」、导师的「材料与任务」）和 ⌘K 的「开始录音」；输入框里的麦克风仍是一句话的语音输入，对一个人记一件事仍走「记一件事」。录音页一页走完准备、录制中、结束、处理中与完成：模式分多人会议（最长 2 小时）和观察速记（最长 10 分钟），可选语言和关联的期次；麦克风未授权时改为打字或上传录音。录制中可以暂停、继续、收起；收起后各页面顶栏出现录音条，站内跳转时录音继续；整页刷新或关闭等同暂停，回到录音页时选择继续录音或结束并整理。**实时文字只做预览**：说话人用编号（说话人 1、说话人 2），不绑定员工；结束后按完整录音重新转写、区分说话人和整理，纪要与事件以完整录音的结果为准，说话人是谁在「待核对」里确认。网络中断时本机继续录、计时照走，实时文字在断开处留一行缺口，恢复后自动补传；结束时还有分段没传完，先补传再进入处理中。结束录音前弹确认，到达时长上限直接结束。处理中可以直接离开，结果进入工作台「进行中的任务」，状态依次为转写中、整理中、部分待核对。打标记、随手记、@某人与手机端一致，本次比赛的工程不接入这三个工具（2026-10-25 确认） |
| DY-17 | 面评导入 | 北森面评只能导出 PDF，系统按版式读出每位候选人的面评，HR 在预览里逐行确认「这是谁」；只导入已入职的人，淘汰、未入职、导入过的行跳过。导入的面评作为「招聘评估」事件进档案时间线（需求定稿 v1.2 §3.9.2），面试原量表原样保存，标「原量表 · 单独保存」，不换算成维度分、不进能力象限；导师 / 助教看不到招聘评估类资料，按来源类别判断，不按类型名；非管理岗的「管理能力」写「管理能力 · 非管理岗免评」；没读出的分对照页面图补录。面试官只能关联到人员目录里已有的人，候选人在目录里查不到时这一行是「待认人」，放进待核对。**导入后人员关联和面试官关联只读**：要更正，先用导入页上常驻的「撤销导入」撤回（按人和时间记审计），改好关联再重新导入；导入后更正的流程放到赛后。**批次状态从各行推出来，不单独存**：还有没处理完的行就是「部分导入」，每一行都已导入或已跳过才是「已导入」（2026-11-01 确认） |
| DY-18 | 回执、待认人与接手的事 | 回执按文件和事件分别计数（处理中、待核对、待确认、已确认），可以逐条部分确认，全部处理完显示「已完成」。说话人、人名等身份还没确定的事只显示「待认人」和原件里的这一处，不显示 AI 草拟和建议分；确认是谁以后才整理这件事、给建议分。评价关系到期后没做完的事由 HR 重新分派，每条接手的事指向具体那件事（某人某周的对人复盘、某件事的建议分），按那件事的实际状态判断办完：复盘确认、建议分确认后从待办里移出，接手记录保留并写「已办完」（2026-11-01 确认） |

## 4. 人才项目与关键节点复盘

### 4.1 入口

侧栏「人才项目」下有两个页签：

- **进行中的一期**（当前为 XEngineer 第六期）：学员、课题、每周节奏、对人复盘与结营。
- **关键节点复盘**：所有人才项目的关键节点和复盘。导师视角没有这个页签。

### 4.2 关键节点

每期人才项目有自己的关键节点，按时间排列。XEngineer 第六期为：W4 周评 → 中期盘点 → 里程碑路演（MS1–MS4）→ 结营评审 → 留用与落位。其他人才项目先用期次本身的节点（如入营名单确定、提前批 offer 锁定、评审结束）。

节点有四种状态：已复盘、待复盘（日期已过、还没有署名的复盘）、进行中（留用与落位在方案确认前）、未开始。状态同时用点的形状和文字区分。

### 4.3 节点复盘的三段

1. **结果**：从现有数据计算，不手填。例如 W4 周评的提交人数与三档分布、中期盘点的落位与资料不足人数、各组 MS1–MS4 平均分、结营结论与去向分布、留用沟通与部门待定人数、判断对照的不一致人数。能回到来源页面的给出入口。
2. **复盘**：HR 写「做得好」「要改进」两组，一行一条，保存后署名，改过的次数和旧版本保留。没有署名的复盘时，HR 看到 AI 草拟（只从上面的结果取数，标明「AI 草拟 · 仅供参考」），可以采用或改写；管理者只看署名的复盘，没有时显示「待 HR 复盘」。
3. **改进事项**：挂在节点下的行动，沿用五种状态（待沟通、进行中、已执行待观察、已复盘、未执行），未执行要写原因。由这个节点产生的盘点、判断对照或方案生成的行动自动挂在该节点下；HR 也可以直接加一条改进事项。

项目找人和「值得聊一聊」生成的行动不属于某个节点，放在页面左栏下方的「其他行动」里跟进。版本 Y 不做逐条行动的任用后复盘。

### 4.4 不变的规则

复盘与改进事项不产生分数，不改变任何人的维度分、象限、档案版本和状态信号；判断对照生成的改进事项只作用于人才评价规则。

## 5. 权限要点

在版本 X 权限规则（PRD v1.0 与 v1.2～v1.6）的基础上，按三种角色收敛：

| 能力 | 管理者 | HR | 导师 |
| --- | --- | --- | --- |
| 看人员档案与象限 | 全部 | 负责的人才项目范围 | 所带学员；看不到象限 |
| 记录关键事件、确认本人评分 | 可以 | 可以 | 所带学员 |
| 对人复盘的评价与分数 | 只读 | 可以采用、改写、修正 | 所带学员可以采用、改写、修正 |
| 评分复核、象限校准、留用与落位方案 | 只读 | 处理与确认 | 无 |
| 人才项目关键节点复盘 | 看署名的复盘与改进事项 | 写复盘、管理改进事项 | 无 |
| 人才评价规则 | 确认发布 | 起草、提交 | 在用到规则的地方看当前版本、提修订建议 |

## 7. 沿用与不纳入

- **全部沿用**：AGENTS.md 中的产品不变量；关键事件维度分与行为锚点；2×2 能力象限与校准冻结；项目要求匹配的四种状态；证据分层与来源回溯；值得关注的入选规则（v1.4～v1.5）；关注与推荐方向（v1.5）；人才评价规则的修订、预览、确认与生效（v1.6）。
- **不纳入版本 Y**：部门负责人与员工视角及其页面；管理者推动事项与结果回流（v1.4）；首页审批组织调整方案；逐条行动的任用后复盘。
