## 1. 新增的决定

| 编号 | 议题 | 决定 |
| --- | --- | --- |
| D-42 | CEO 首页 | CEO 首页只保留四块：**找人**、**值得关注**、**我推动的事项**、**判断提醒**。「变化」、进行中的任务、上传材料、组织调整与资料缺失类信息不再出现在 CEO 首页，改由 HRBP 与负责人的工作台承担（见 3.19）。修订 v1.3 D-41 与 3.18 中 CEO 一行 |
| D-43 | 值得关注 | 「值得关注」分三类：**新发现**、**突出表现**、**需要介入**。每一类都有写明的入选规则和规则版本（`watch-v1`），按触发时间排列；**不按分数挑人、不排名、不显示分数或均值**；「资料不足」和「一段时间没有新事件」不作为需要介入的理由（见 3.20） |
| D-44 | AI 线索 | AI 从材料里发现的线索（如多人在不同会议里独立提到某人）必须引用来源，经 HRBP 核实后才进入 CEO 的「值得关注」，并署核实人；未核实的线索 CEO 看不到。负责人和 HRBP 可以提名，提名必须引用至少 2 条来自不同事件的已确认记录 |
| D-45 | 推动 | CEO 可以对「值得关注」里的人发起四种推动：**进一步了解**（安排一次沟通）、**验证**（补证据或设为重点跟踪）、**培养**（安排发展机会，生成行动）、**任用讨论**（作为手动补入的候选人带入找人或用人方案）。每次推动必须指派一位负责人（该员工的 HRBP 或负责人）（见 3.21） |
| D-46 | 推动结果回流 | 推动的结果由负责人记录并确认，作为**管理观察**进入该员工档案时间线，标明「来自 CEO 推动」和确认人；结果不自动产生维度分，也不改变象限（见 3.21.3） |
| D-47 | CEO 与判断复盘 | 页面名称沿用「判断复盘」（「校准」在本产品里已指分差校准和象限校准会，不再复用）；校准队列不被替代。CEO 首页只放轻量的「**判断提醒**」：最多 2 条批次级差异，一行一条，不显示 AI 假设，也不显示按评价人的数字（D-39 不变）。CEO 在判断复盘页可以「请 HRBP 复核」并写评论；归因与评价标准修订仍由 HRBP 确认（见 3.22） |
| D-48 | CEO 外壳减噪 | CEO 视角下：顶栏搜索收成图标，⌘K 照常可用；导航不显示「校准队列」「标签库」（直接访问的权限不变）；「盘点」不显示草稿数角标；日期行不写盘点进度（见 3.19.3） |
| D-49 | 职业通道路径 | 需求文档 v1 给出的多级路径（如产品架构师 → 产品负责人 → CEO、TS / FDE → 产品经理 → 产品负责人）不在人才发展大图（S2）里，**待确认来源**后作为通道清单的新版本加入。通道只解释可迁移的路径，不改变候选人排序，也不改变候选资格（修订 v1.3 3.15.1，见 3.23） |
| D-50 | 按项目看 | 「值得关注」提供「按人看 / 按项目看」两种查看方式：按项目看时，同一批入选的人按依据事件所在的项目或批次分组，点项目看相关人才。不单独设「最近关键事件」一块，入选规则不变（见 3.20.2） |

TD（人才发展）的工作并入 HRBP 视角，五类用户不变（D-18、D-39 不变）。

## 2. 输入来源与理解

### 2.1 需求文档「CEO 界面调整需求 v1」

该文档把 CEO 的核心诉求归为两个问题：需要关键人才时，能不能更有依据地找到人；能不能从入职后的关键事件里发现过去判断的偏差，让以后的识别更准。不能回答这两个问题的功能，不占 CEO 首页的重要位置。

| 需求项 | 理解 | 对应 |
| --- | --- | --- |
| 首页只留四块：找人才、值得关注的人才、判断校准、我推动的事项 | 与 v1.3 的方向一致，进一步去掉「变化」、任务队列和上传卡 | D-42 |
| 顶部全局搜索与大输入框重复，顶部搜索弱化 | 保留 ⌘K，顶栏只留图标 | D-48 |
| 「变化 12 条 / 规则命中数」改为「值得关注 · 8 人」；四类变化改为新发现 / 突出表现 / 需要介入；只看 3–5 条精选 | CEO 关注的是人，不是系统变化量。「精选」必须有规则，不能变成按分数挑人 | D-43、D-44 |
| 「近 3 个月 vs 历史版本」放进人员详情的「判断演变」 | 按人员档案已有的「档案版本」与能力走向对比来理解；不把判断复盘的跨阶段对照写进档案（v1.3 3.16.5 第 3 条不变） | 3.19.2 |
| 待办改为「我推动的事项」，只保留 CEO 需要决策或跟进的事 | 待 CEO 确认的事置顶，其后是 CEO 发起、仍在推进的事 | 3.19.1 |
| AI 文件处理队列、上传大卡片移出 CEO 首页 | 移到 HRBP 与经办人的工作台；CEO 仍可以在输入框里附带材料 | D-42 |
| 「校准队列」升级为「判断校准」 | 两者是不同的事：校准队列处理单条分数的分差，判断复盘检验一批判断。沿用「判断复盘」命名，校准队列保留给 HRBP | D-47 |
| 判断差异要提示「需要复核，不代表员工退步，也不代表一定是面试官判断错」；复核方向为评价模型、面试官判断、评价场景、培养与环境 | 与 v1.3 的双向对照（D-37）和五类归因一致；四个方向分别对应「评价标准」「评价人」「评价方式与信息不足」「本人或环境变化」，「后段评价偏差」保留为第五类。可以借用问题式文案 | 3.22 |
| 保留每次评价及依据的历史版本，不能把 S 改成 A 覆盖原记录 | v1.3 3.16.6 已规定：评价记录保留所用版本，不静默重算 | 不变 |
| 找人要支持跨岗位、跨职业通道，并解释为什么推荐某人；改一个条件（如「必须有管理经验」改为加分）后重新解释 | v1.2 的需求卡、四种匹配状态和逐项证据已覆盖解释与就地修改；跨通道的多级路径来源待确认 | D-49 |
| CEO 推动进一步了解、验证、培养或任用讨论，结果回到人才档案 | 新增「推动」，负责人确认后回流到档案时间线 | D-45、D-46 |
| CEO 和 HRBP / TD 的职责边界 | CEO 发起和推动；HRBP 核实关注依据、分析案例、提出标准修改、跟进记录结果 | 3.24 |

### 2.2 CEO 首页走查（v1.3 原型，1440 × 900）

| 问题 | 现象 | 对应 |
| --- | --- | --- |
| 层级 | CEO 最该处理的「要你确认」在首屏之下（约 1050px 处）；「变化」和「进行中的任务」占了首屏的大部分高度 | 3.19.1 |

### 2.3 CEO 首页组织方式的业务评审意见

评审意见建议的顺序是：值得关注的人（新发现 / 突出表现 / 需要介入）→ 最近关键事件（按 Landing 批次、XEngineer 期次、新转化团队、海外加速搜索等，点事件看相关人才）→ 我的推动（我发起的人才探索、我需要决策或推动的事）→ 判断提醒（轻量，只显示 1–2 条，不叫「判断校准」）。

| 建议 | 结论 | 理由 | 对应 |
| --- | --- | --- | --- |
| 四块里没有找人入口 | 不采纳：找人输入框保留在首屏，做得更紧凑 | 需求文档 v1 把「需要关键人才时找到人」列为 CEO 的第一核心诉求，v1.3 评审也指出输入框是 CEO 最常用的功能 | 3.19.1 |
| 「最近关键事件」单独一块 | 缩小范围：并入「值得关注」，加「按项目看」 | CEO 按业务场景想问题，项目视角有价值；但单独一块与值得关注、我的推动重叠，也容易退回「变化」式动态流 | D-50 |
| 「我的推动」放在值得关注之后 | 采纳；桌面端放在右栏，首屏可见 | 待 CEO 确认的事仍要首屏可见 | 3.19.1 |
| 判断类信号做轻量提醒，只显示 1–2 条 | 采纳：首页叫「判断提醒」，详情与「请 HRBP 复核」在判断复盘页 | CEO 只需要知道哪里值得复核，案例与过程留给 HRBP | D-47、3.22 |

## 3. 对 v1.3 的变更与新增规则

### 3.19 CEO 首页（修订 v1.3 3.18 中 CEO 一行）

#### 3.19.1 结构

| 块 | 内容 | 规则 |
| --- | --- | --- |
| 找人 | 首屏第一视觉重点。一句话输入框，提示只讲找人（描述业务目标、必须项和加分项）；主按钮「开始找人」；示例只放找人的句子；目标角色模板作为次要入口放在输入框下方 | 输入框仍能识别其他意图（如记录一件事），但不在首页提示；去掉附件按钮、「/ 查看命令」和快捷键提示 |
| 值得关注 | 三类人数（新发现 / 突出表现 / 需要介入），下面列最近 4 条；可以按类别筛选、展开全部，或切到「按项目看」 | 见 3.20 |
| 我推动的事项 | 置顶：需要 CEO 本人确认的事（如待确认的用人方案）；其后：CEO 发起、仍在推进的事——找人需求、推动、判断复盘复核请求；各自显示负责人、状态和最近进展。完成 7 天内显示在「近 7 天有结果」里，之后只留在原处 | 不显示 HRBP 或负责人自己的待办；置顶部分在 1440 × 900 首屏内可见 |
| 判断提醒 | 最多 2 条值得复核的批次差异，一行一条：批次、偏差最集中的维度、归因状态；点进判断复盘页 | 见 3.22 |

桌面端：找人横跨全宽；其下左侧为「值得关注」，右侧为「我推动的事项」和「判断提醒」。手机端顺序：找人 → 我推动的事项 → 值得关注 → 判断提醒。

四块之间不加编号，它们不是先后步骤。

#### 3.19.2 移出首页的内容去哪里

| 内容 | 去向 |
| --- | --- |
| 变化（能力走向、活跃度、象限偏移、团队分布） | HRBP 与部门负责人的工作台保留（v1.2 3.14 不变）；CEO 在人员档案里看单人的能力走向和档案版本对比，这就是需求方说的「判断演变」 |
| 进行中的任务、上传材料 | HRBP、经办人的工作台；CEO 仍可以在输入框里说话或录音 |
| 组织调整方案 | 「盘点」页面；需要 CEO 确认时出现在「我推动的事项」的置顶部分 |
| 其他人的待办 | 各自的工作台；CEO 首页不再显示「还有 N 件在推进」 |

#### 3.19.3 CEO 外壳

| 位置 | CEO 视角 | 其他视角 |
| --- | --- | --- |
| 顶栏搜索 | 只显示图标，点击或 ⌘K 打开搜索 | 不变 |
| 导航 | 不显示「校准队列」「标签库」；「判断复盘」保留 | 不变 |
| 「盘点」角标 | 不显示草稿数 | 不变 |
| 日期行 | 只写日期与范围（全公司） | 不变 |

导航隐藏不是权限控制：CEO 直接打开校准队列、标签库仍按原权限显示（v1.2 3.5.3 不变）。

### 3.20 值得关注（新增，规则版本 `watch-v1`）

#### 3.20.1 三类与入选规则

| 类别 | 规则 | 来源 |
| --- | --- | --- |
| 新发现 | **N1 资料从无到有**：入职或并入后此前没有已确认分；近 90 天内，同一维度有 2 条来自不同事件、4 分及以上的已确认分 | 系统按规则算出 |
| 新发现 | **N2 AI 线索**：AI 从会议纪要、周报等材料中发现的线索，必须引用原文位置 | HRBP 核实后可见 |
| 突出表现 | **T1 能力走向走高**：与「变化」同口径（change-v1：近 3 个月均值比之前 9 个月高 1.5 及以上，近 3 个月至少 2 条） | 系统按规则算出 |
| 突出表现 | **T2 提名**：负责人或 HRBP 提名，写一句理由，引用至少 2 条来自不同事件的已确认记录 | HRBP 核实后可见 |
| 需要介入 | **I1 能力走向走低**：与「变化」同口径 | 系统按规则算出 |
| 需要介入 | **I2 值得聊一聊未处理**：「值得聊一聊」信号打开 14 天以上，还没有人处理 | 系统按规则算出 |
| 需要介入 | **I3 重点跟踪逾期**：重点跟踪过了约定日期还没有更新 | 系统按规则算出 |

不作为入选理由的情况：资料不足；一段时间没有新事件；只是参考位置跨象限（留在 HRBP 的校准队列）；项目进出、调岗。

#### 3.20.2 呈现

| 项 | 规则 |
| --- | --- |
| 每一条 | 人、所属部门、类别、一句话原因（用业务语言，如「内生动力已有两件事可以印证」）、入选规则编号与版本、证据引用、核实人（N2、T2）、已经在做的事（重点跟踪、行动、CEO 推动） |
| 不显示 | 分数、均值、百分比、排名、象限位置 |
| 排列 | 按触发时间从新到旧；首页显示最近 4 条，可以展开全部；不设人数上限，也不为凑数降低门槛 |
| 按项目看 | 同一批入选的人按依据事件所在的项目分组，Landing 议题归到所在批次；没有挂项目的归到「不在具体项目里」；组之间按最近触发时间排，组内不排序 |
| 一人多条 | 同一个人只出现一次，归到最近触发的类别，其余命中的规则并列写出 |
| 计数 | 写「新发现 3 人」，没有命中写「暂无」，不写 0 分或空状态的负面措辞 |
| 资料不足 | 不当作负面信息；需要介入类的文案只写事实和信号，不写「表现差」 |

#### 3.20.3 核实与提名

- N2 与 T2 先进入 HRBP 的待办「待核实」，HRBP 可以「核实」或「不采纳」（不采纳要写理由，线索保留在 HRBP 视图中）；只有核实过的才对 CEO 可见。
- 核实只确认「依据属实、值得 CEO 看到」，不产生分数，也不改变档案。
- 员工本人、导师 / 助教在任何入口都看不到自己或他人是否在「值得关注」里。

### 3.21 推动（新增）

#### 3.21.1 四种动作

| 动作 | 含义 | 负责人要做的事 | 结果形态 |
| --- | --- | --- | --- |
| 进一步了解 | 安排一次沟通，听听本人的想法 | 约谈并记录要点 | 管理观察 |
| 验证 | 现有证据不够，补证据或设为重点跟踪 | 补一条关键事件，或建立重点跟踪（沿用 v1.2 重点跟踪规则） | 关键事件或重点跟踪 |
| 培养 | 安排一次发展机会 | 生成行动（沿用「行动与复盘」，PRD FR-12） | 行动及其复盘 |
| 任用讨论 | 把这个人带进一次找人或用人方案 | 在选定项目的找人里作为「手动补入」的候选人，要求逐项照样核对，不冒充模型推荐（v1.2 3.6.2 不变） | 用人方案中的候选人 |

#### 3.21.2 发起与跟进

| 项 | 规则 |
| --- | --- |
| 发起 | CEO 从「值得关注」的条目或人员档案发起；选动作 → 选负责人（该员工的 HRBP，或其部门负责人）→ 可写一句说明 |
| 负责人看到 | 待办「CEO 请你……」，带 CEO 的说明和发起依据（值得关注的规则与证据） |
| 状态 | 待处理 → 进行中 → 已有结果；也可以取消，取消要写理由 |
| CEO 看到 | 「我推动的事项」里显示负责人、状态、最近进展；已经推动过的人，在「值得关注」里显示「已推动」，不重复发起同一种动作 |

#### 3.21.3 结果回流

- 负责人记录结果并确认后，结果作为**管理观察**进入员工档案时间线，标明「来自 CEO 推动」、动作、负责人和确认时间，可以回到发起依据。
- 结果不自动产生维度分；如果结果本身是一件关键事件，走正常的事件记录与打分流程。
- 管理观察的可见性不变：员工、导师 / 助教看不到 CEO 推动的结果，也看不到自己被推动过。
- 推动不改变象限、档案版本和状态信号。

### 3.22 CEO 与判断复盘（修订 v1.3 3.16.4 的 CEO 可见内容表述，权限不变）

| 项 | 规则 |
| --- | --- |
| 首页「判断提醒」 | 最多 2 条，一行一条：批次、偏差最集中的维度（写成「8 人中 2 人前段偏高」）、归因状态（待 HRBP 归因 / 归因已确认 / HRBP 复核中）。同一维度前段偏高与偏低合计不少于 2 人才算有差异；没有差异的批次不出现 |
| 文案 | 差异写成「需要复核」，不写成员工退步，也不直接认定评价标准或评价人有错 |
| 不显示 | AI 归因假设、按评价人的任何数字或案例、被评价人名单 |
| 请 HRBP 复核 | CEO 在判断复盘页发起，写一句评论（如「第二期内驱力还有 2 人偏高，看看是不是面试追问不够」）；进入 HRBP 待办，显示在 CEO 的「我推动的事项」 |
| HRBP 处理 | 在判断复盘页看到 CEO 的请求，复核后写回复并标为已复核；归因、改进动作和评价标准修订仍按 v1.3 3.16.5、3.16.6 由 HRBP 确认 |
| 复核方向的问题式文案 | 评价标准：等级定义和观察锚点是否一致？评价人：提问、追问和评分是否有偏差？评价方式与信息不足：两个阶段观察到的是同一种能力吗？本人或环境变化：任务难度、带教、资源是否影响了表现？后段评价偏差：后段评价口径是否偏严、证据是否够？ |

## 10. 风险提示

- **「精选」滑向打分排行。**「值得关注」最容易被做成「高分人才榜」。规则固定、按时间排、不显示分数、不设凑数门槛，是硬约束，不能为了演示效果放宽。
- **CEO 推动的分量。**CEO 发起的事天然有压力，负责人可能为了交代而写结果。结果只作为管理观察进档案，不自动产生分数，取消要写理由，避免「CEO 关注过」变成隐性标签。
